# 多 Agent 协作：本地小 Agent 对"强模型前置产物"的续分析——改进设计

> 缘起（用户真实工作流，务必先读懂再往下看）：
> 用户**大多数情况下不会**把一个裸 APK 直接丢给本地 rev-agent 逆向。真实流程是——
> 先用**更强的 agent**（Claude Code / Codex 等）对 APK 做**前置分析**，产出一整个**案卷目录**：一堆 Markdown 分析文档 + 结论、Frida hook 脚本与运行输出、LSPosed 结果、网络抓包（pcap/har）、native/so 的 dump、各种中间产物。
> 然后用户希望**本地小 agent（Qwen3.6-35B）接手这个案卷目录继续分析**——复用、核验、扩展、补链、答新问题。
> 本文深度分析：**面向"续分析已有案卷"这个场景，rev-agent 该怎么改**。合规：全程只读分析既有产物 + 防御视角，不产出破解/重打包。

---

## 一、核心认知（三个 reframe，决定后面所有改进的方向）

### 认知 1：角色从"逆向器"变成"接手案卷的常驻分析员"
rev-agent 现在的隐含设定是**首席侦查员**：给一棵反编译源码树，从零开始探索、定位。
而这个场景里它是**接手别人办了一半的案子的初级分析员**：案卷里已经有资深探员（强模型）写好的结论、现场证据（动态 trace / 抓包）、物证（源码 / so dump）。它的工作不是重新破案，而是：
- **读懂并信任/核验**前人结论（而不是从头再来）；
- 用**更便宜、可无限跑**的本地算力，做前人没做完的**核验、补链、交叉印证、扩展**。

这一句话推翻了当前的整个入口假设（见 §三）。

### 认知 2：这个场景恰好把 rev-agent 最大的短板变成优势
我在 [[能力边界与上限]] 和 `完整性审查` 里标定过：rev-agent 是**纯 jadx 静态**，看不到 native/Flutter/IL2CPP、看不到运行时值、看不到网络——动态/native 必须人接管。
**但在这个场景里，运行时真相已经被 Frida / 抓包 / 强模型固化成了文本**。小 agent 读这些文本，就等于"看见"了它自己抓不到的动态/native 证据：
- Frida hook 输出里有某混淆方法的**真实返回值 / 解密后的 key**——静态啃不出的，读日志就有；
- pcap/har 里有**真实的鉴权端点、请求体、token**——静态只能猜"可能有服务端校验"，抓包直接坐实；
- 强模型可能已经跑过 blutter/Il2CppDumper，把 `.so` 里的类/方法**dump 成了文本**——小 agent 读 dump 而不是啃 `.so`。

→ **静态天花板不是靠让小 agent 变强来突破，而是靠"喂给它别人已经捕获的动态证据"来绕过。** 这个工作流本身就是我一直找的那个"补齐动态/native 缺口"的落地路径（呼应 `完整性审查` 的最高杠杆结论）。

### 认知 3：为什么"续分析"该用本地小 agent，而不是再开一个强 agent
用户可能会问：既然强 agent 更聪明，续分析为什么不继续用强 agent？四条真实理由：
1. **成本**：案卷目录很大（几十上百个 MD + 大 pcap/har + 大日志）。让云端强 agent 反复通读整个大目录烧钱；本地 agent token 近乎免费，适合"反复啃大语料"的粗活。
2. **隐私**：案卷含 Frida trace、抓包、目标 App 内部结构，是敏感物料。续分析留在本地 lemonade 跑，**天然不上云**（契合用户"逆向数据不上云"的本能，即便公开仓库放松了文档层面）。
3. **常驻/迭代**：强 agent 适合"啃硬骨头的突破"，一次性、贵。小 agent 适合当**常驻工人**——增量地一遍遍过案卷、维护和扩展结论，把强 agent 留给真正卡住的地方。
4. **廉价验证层**：强 agent 也会幻觉。本地 agent 可以当**便宜的独立复核员**，拿原始证据逐条 re-check 强 agent 的结论（贵的发现一次、便宜的验证多次）。

**定位一句话**：rev-agent = **住在案卷文件夹里、廉价、本地、常驻的分析员**，在昂贵的强 agent 两次介入之间持续把案卷往前推。

## 二、真实案卷的构成 × 每类工件的处理策略（路由表）

一个典型的"强模型前置分析"目录里会有这些东西。关键是给每类工件定**信任级别**（一手证据 vs 二手结论）+ **正确工具** + **rev-agent 该做的动作**：

| 工件类型 | 典型形态 | 信任级别 | 预处理/工具 | rev-agent 该做的动作 |
|---|---|---|---|---|
| **强模型分析 MD** | `analysis.md`/`结论.md`/`README` 一堆 | 二手结论（线索，非事实） | 大文件先出**大纲**（标题+行号），按需读段 | **开局先读**，当作假设/线索；承重结论要拿一手证据核验；引用标 `doc:line` |
| **反编译源码树** | `*-jadx/sources`、`smali/` | 一手（可核验） | 现有 grep/read_file（**核心能力**） | 静态核验前人对代码的断言；补 file:line |
| **Frida 脚本+输出** | `hook.js` + `frida.log` | 一手（运行时真相） | 读文本日志；大日志先 grep 定位 | 提取静态看不到的**运行时值/调用序列/真实返回**，与代码对齐 |
| **LSPosed 结果** | 模块日志 | 一手 | 读文本 | 看装了哪些 hook、运行时观察到什么 |
| **网络抓包** | `*.pcap`/`*.pcapng`/`*.har` | 一手（网络真相） | **tshark / jq 先转文本摘要**（pcap 是二进制，直接读没用） | 提取鉴权端点/请求响应/token；坐实"服务端 vs 客户端"判定 |
| **native/so dump** | ghidra 导出、il2cpp dump、`strings` | 一手（但是别人 dump 的） | 读 dump 文本 | 读**已 dump 的文本**而非啃 `.so`；填静态盲区 |
| **中间 JSON/config** | manifest、strings、entitlement json | 一手 | grep/jq | 交叉引用 |
| **截图** | `*.png/*.jpg` | 一手但**35B 无视觉** | —— | 明确"看不了图"，退回到前人 MD 里对图的转述；**不臆测** |

**两条贯穿全表的铁律**：
- **一手 vs 二手要分清**：MD 结论是"某某说的"（二手），代码/trace/抓包是"我核到的"（一手）。这直接影响 §五的反幻觉铁律在本模式下的措辞。
- **二进制/图像不硬啃**：pcap 走 tshark、so 走已有 dump、图承认看不了。宁可路由/承认边界，绝不对读不了的东西编造内容。

## 三、现状为什么不适配（基于真实代码，不空谈）

1. **入口假设写死"输入=一棵源码树"**。`src/preflight.ts` 的 `preflightSourceTree()`：源码级任务若 `--workdir` 下没有 `sources/`/`smali/`/`.java`，直接 **fail-fast 让用户去 jadx**。案卷目录顶层往往是**一堆 MD + pcap + 日志**、源码树只是其中一个子目录——现状 preflight 会**误杀**这种目录（找不到顶层源码树就拦），或即便放行，agent 也**不知道那些 MD/trace/pcap 的存在与价值**。
2. **没有 orientation（定向）阶段**。现在开局直接按"4 阶段渐进探索协议"在源码树里 grep。案卷场景需要一个**先环顾案卷、读前人结论、建案情图**的 Phase 0，当前完全没有。
3. **没有 provenance（出处）概念**。`append_note` 是台账（`agent.ts:447` 永不折叠），但它只记"我发现了 X"，不区分"前人 MD 说的 X"vs"我在代码核到的 X"。混着二手结论和一手证据，35B 极易**把前人的一句话当成自己核实过的事实**往下推。
4. **反幻觉铁律在本模式会误伤**。我加的铁律是"只基于你 read_file 读到并能 file:line 引用的内容下结论"。但案卷里**前人 MD 的一句结论本身就是可引用的语料**（`doc:line`），只是它是二手。铁律需要一条**本模式修正**：二手结论**可以引用**，但要**标明是二手 + 承重时去核**，而不是一律当"没读到=未证实"。
5. **大语料 vs 35B 小上下文**。案卷可能有几万行 MD + 大日志。现在 read_file 是整段读，一个 5000 行的 MD 直接把上下文撑爆。需要**大纲/分段/检索**，而不是通读。
6. **格式盲区**：pcap/har/so 二进制或超大 JSON，现有 shell/grep/read_file 直接读要么是乱码要么撑爆。需要**格式感知的预处理**把它们先降成紧凑文本。

## 四、改进设计（分优先级，每条都给具体落点）

### P0（最高杠杆、改动小、直接决定这个场景能不能用）

**P0-1 新增"案卷模式"入口 + orientation preflight（泛化现有 preflight.ts）**
- 新 flag：`--corpus <dir>`（案卷根目录），与现有 `--workdir`（源码树）分离；`--corpus` 存在时进入案卷模式。也可让 `--workdir` 兼任：若它不是源码树但含多类工件，自动识别为案卷根。
- 把 `preflightSourceTree` 泛化为 `preflightCorpus`：不再"没源码树就拦"，而是**扫一遍案卷根，产出 manifest**——每个文件/子目录 → 类型分类（MD结论 / 源码树 / frida / lsposed / pcap-har / so-dump / config / 图像）+ 大小 + 一行角色。分类靠签名启发式：
  - `*.md` → 结论文档（顶层的 `README/INDEX/SUMMARY/结论*` 优先级最高）
  - `sources/`、`*-jadx/`、`smali/` → 源码树（复用 `looksLikeSourceTree`）
  - `*frida*`/`*hook*.js`、含 frida 标记的 `*.log` → 动态 hook
  - `*.pcap*`/`*.har` → 网络
  - `*.so`、`*il2cpp*`、`global-metadata*`、`*ghidra*`、`strings*.txt` → native dump
  - `*.png/*.jpg` → 图像（标注"视觉不可读"）
- preflight 输出这份 manifest 注入 system（见 P1-3 的稳定前缀位置），让 agent **开局就知道案卷里有什么、该先读什么**。

**P0-2 provenance（出处）分级 + 反幻觉铁律的本模式修正**
- system 协议加"出处纪律"：每条结论必须带**来源标签**——`[前人MD]`（二手，标 `doc:line`）/ `[代码]`（一手，`file:line`）/ `[动态trace]` / `[网络]` / `[我的推断]`。
- 反幻觉铁律补一条本模式款：
  > 前人 MD 里的结论**可以引用**，但必须标明是二手（`doc:line`）；**承重结论**（最终定性、给用户的修复方案所依赖的那条）要尽量拿一手证据（代码/trace/抓包）核实后升级为一手。**核不到就说"前人称 X，我未能独立证实"**，绝不把二手当一手，也绝不因为"没在代码里读到"就否定一条本就属于动态/网络证据的前人结论。
- `append_note` 台账升级为**带出处的案卷更新**：`已核实(一手) / 沿用(二手未核) / 与前人矛盾 / 新发现 / 仍开放` 五类。

**P0-3 handoff 契约（强 agent ↔ 小 agent 的交接约定）**
- 约定：让前置强 agent 在案卷根放一个 `INDEX.md`（或 `HANDOFF.md`）——列出已知结论、证据文件清单、开放问题。rev-agent **开局第一件事读它**。
- 若不存在，rev-agent 用 P0-1 的 manifest **自动生成一份** `INDEX.md` 草稿，既当自己的定向图，也回馈给用户/下一轮强 agent。→ 形成**双向可迭代的交接文件**，是多 agent 协作的黏合层。

### P1（把场景做深）

**P1-1 格式感知预处理（把二进制/超大工件降成紧凑文本）**
- 不让 35B 硬读二进制。preflight 或专用工具做一次性转换，产出 `*.digest.txt`：
  - pcap/pcapng → `tshark -q -z http,tree` / 端点+方法+状态摘要；
  - har → `jq` 抽 `entries[].request.url/method` + 响应码 + 关键 body 字段；
  - 大 MD（>N 行）→ **大纲**（标题树 + 每节行号范围），agent 按需读段而非通读；
  - 大日志 → 先 grep 关键标记（方法名/URL/异常）再定点读。
- 这些都是**本地 CLI**（tshark/jq），不碰 lemonade，不违单并发铁律。

**P1-2 跨源三角验证协议（这个场景真正的增值）**
- system 协议明确要求**跨工件三角印证**，而不是单看一类：
  > 一条结论尽量用两个以上来源互证：`静态代码 ↔ 动态 trace ↔ 网络抓包 ↔ 前人结论`。例：前人 MD 说"VIP 走服务端校验" → 在代码里找到那个端点常量 → 在 har 里确认该端点真被调用且返回体含 entitlement → 三方一致才定性。
- 这把静态盲区用动态/网络证据补上，正是认知 2 的落地。

**P1-3 上下文/检索：manifest 稳定前缀 + 按需检索**
- 遵守 [[SWA稳定前缀铁律]]：manifest / INDEX 这类**相对稳定**的定向信息放 system 头部稳定区；每次检索到的**具体段落**拼在 messages 末尾。避免案卷一大就"越读越卡"。
- 检索用**grep across corpus + 定点 section-read**，**不上向量库**（见 §五辩证）。read_file 增"按行范围/按标题读段"能力，配合 P1-1 的大纲。

### P2（锦上添花）

**P2-1 verifier 角色（把小 agent 当强 agent 的廉价复核层）**
- 一个 `--mode verify`：输入前人 MD 的结论清单，逐条拿一手证据 re-check，输出 `证实/证伪/无法核实（缺证据）` 三态报告。经济上合理：贵的发现一次，便宜的验证多次、可反复跑。

**P2-2 结构化案卷输出（机器可合并的案卷增量）**
- append_note 之上再出一份结构化 `case-update.json`（发现/出处/状态/证据链），供下一轮强 agent 或用户直接 merge，而不是只留自由文本。让 rev-agent 成为多 agent 流水线里一个**输出可被下游消费**的节点。

## 五、辩证：哪些**不要**做（避免过度设计）

1. **不要上重型向量 RAG**。案卷是个文件夹，典型规模 grep + 大纲 + 定点读段足够；上 embedding/向量库是重装备、维护成本高，且 [[三提议裁决]] 已判过"文档 RAG"字面版否决——主瓶颈从来是**行为**不是检索花活。**但本场景是那个裁决的一个正当例外**：这里知识是**外部真实存在且量大**的（案卷），不是"泛逆向知识蒸馏"那种伪需求，所以**轻量检索**（grep+section-read）值得做，**重型向量库**仍不值得。这条边界要守住。
2. **不要让 agent 硬解二进制/native**。pcap 走 tshark、so 走已有 dump、图承认看不了。让 agent 亲自 parse `.so`/`.pcap` 是死路，也是幻觉高发区。
3. **信任的平衡点**：既不能盲信前人 MD（会继承并放大强 agent 的错），也不能因"没在代码里读到"就把动态/网络类前人结论一律打成"未证实"（那会否定本来正确的一手动态证据）。正解=**出处分级 + 承重才去核 + 核不到如实说二手**。
4. **不要重做已完成的工作**。这个场景的全部价值在"续"——沿用前人已定的、只补没做完的。开局若把前人结论重新推一遍，等于把小 agent 当首席侦查用，既慢又容易在混淆代码里翻车（正是 35B 的天花板）。协议要显式说"**先读结论，别重推**"。

## 六、与既有裁决/审查的关系（一致性检查）

- **`完整性审查`（动态/native 必须人接管）**：本场景是该结论的**正向解法**——不靠 rev-agent 自己做动态，而是**摄入**人/强 agent 已捕获的动态证据文本。缺口从"agent 做不了动态"变成"agent 会不会用别人做好的动态结果"，后者纯靠本文的摄入/出处/三角验证改进即可拿下。
- **[[三提议裁决]]（文档 RAG 字面版否决）**：本文 §五-1 给出**正当例外与边界**——轻量检索做、重型向量库不做。
- **[[SWA稳定前缀铁律]]**：manifest/INDEX 进稳定前缀、检索段落拼末尾，直接复用。
- **[[能力边界与上限]]（README 标定）**：本场景**扩展了有效边界**——rev-agent 单独面对 Flutter/Unity/native 仍是"识别+路由+不幻觉"；但**当案卷里已有对应 dump/trace 时**，它能读那些文本参与分析。README 边界章节应加一句："**有前置产物时，通过摄入动态/native 证据文本，有效分析范围显著扩大**。"

**先做 P0 三件**：它们决定"这个场景能不能跑起来"；P1/P2 决定"跑得多好"。

## 八、结论
用户的真实工作流揭示了 rev-agent 一个**被低估的高价值定位**：不是孤胆逆向器，而是**多 agent 逆向流水线里那个廉价、本地、常驻、会读案卷的续分析节点**。这个定位一举把它最大的短板（静态天花板）反转成优势——因为动态/native/网络真相已被前置强 agent 与 Frida/抓包固化成文本，小 agent 读文本即可参与。要吃下这个场景，核心改动不大且聚焦：**案卷定向（manifest+INDEX 契约）+ 出处分级（一手/二手，反幻觉铁律本模式修正）+ 轻量检索（grep+大纲，不上向量库）+ 跨源三角验证**。守住"只读、分出处、不硬啃二进制、不重推、不过度设计"五条边界，rev-agent 就能从"给我个 APK"进化到"给我个案卷文件夹，我接着办"。
