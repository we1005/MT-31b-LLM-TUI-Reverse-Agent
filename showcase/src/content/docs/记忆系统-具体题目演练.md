# 记忆系统·具体题目演练（一条多跳链路的全过程实录）

> 用一道**真实完成**的多跳链路题（`via-01-adblock-chain`，无引导基线，带全部记忆机制）逐步演示：本地 35B 在记忆系统支撑下如何**不发散、不断链、追完必收尾**地追出一条 3-4 跳调用链，并逐条对上每个设计机制的实际作用。数据取自 `ablation/via-01-adblock-chain.BASE.s1.{err,out}`（消融 BASE 配置的实跑轨迹）。

## 题目
> workdir: `.../loop-apks/via-jadx/sources`（Via 浏览器反编译源码树）
> 从 WebView 的 `shouldInterceptRequest` 入口出发，完整追出"一个被拦截的请求最终返回什么"这条链路（入口 WebViewClient 子类 → 抽象基类默认实现 → 组合/分发子类的迭代 → 最终 WebResourceResponse）。

**Ground truth（云 agent 读码验证）**：入口 `p4.j`（两个 `shouldInterceptRequest` 重载都调 `f10965a.F(...)`）→ 静态类型抽象类 `p4.a`（`F()` 默认 `return null`）→ 组合子类 `p4.b`（在 `f10963a` 列表上迭代，取第一个非 null）→ 拦截时返回空 `WebResourceResponse("text/plain","UTF-8", ByteArrayInputStream(new byte[0]))`。

## 结果（agent 结论，与 GT 对齐）
agent 正确追出并写出完整链路：`p4.j`（两个重载都委托 `f10965a.F`）→ 抽象基类 `p4.a`（`F()` 默认 `return null`）→ 组合子类 `p4.b`（`F()` 迭代 `this.f10963a` 列表、取首个非 null，`G()` 加元素、`H()` 判空）→ 拦截时返回 `new WebResourceResponse("text/plain","UTF-8", new ByteArrayInputStream(new byte[0]))`（空字节流）。**机械锚点判分 recall=0.70**，`conclusion=1`，全程 `interventions=0`（零介入、零卡住）。

## 每个记忆机制在这一跑里的实际作用（对上设计）

| 机制 | 轨迹中的证据 | 起了什么作用 |
|---|---|---|
| **带外结构化 Ledger（系统自动抽取，零 LLM）** | reads 0→4、greps 0→3、hops 0→2 随工具调用**自动累加**（模型没被要求"写台账"） | 治"小模型不自律记台账"：每次 read/grep 后系统自动记账，追踪状态不靠模型自觉。收尾时 `hops=2` 直接成链路草稿。 |
| **稳定前缀（台账拼 messages 末尾，system 静态）** | prefix-cache 命中率全程 **66%–90%（均 78%）**，ctx 从 361 长到 10492 也没塌 | 台账每步在变但只拼在末尾 → `[静态 system + 只追加历史]` 是稳定 KV 前缀，每步只重算尾巴。**§8 消融实测：放 system 头部则 duolingo-2 上掉到 37%**。这里 78% 就是该设计的收益现场。 |
| **零-LLM 调用边派生（2b-1）** | step5 出现 `hops=1`，SCORECARD `hops=2 ✓1`——其中有 corroborated（✓）边 | 从"已 grep 符号 + 读到内容"确定性派生 caller→callee 边并交叉核验（✓），不靠模型自述"跳N"格式（旧法实测 ✓率仅 26%）。 |
| **可逆折叠（写入即落盘 / compactHistory）** | `folded=0`（ctx 仅 10k，远未逼近 160k 阈值） | 工作集小就**不折叠**以保稳定前缀——正是设计意图（"逼近上限才折一次止血"，不做每步重折叠）。这一跑证明日常小 ctx 下折叠机器**不该触发**，也没触发。 |
| **去重守卫 + 死锁修复（2b-e）** | `dedup=0`（没有重复 read/grep） | 本跑无重复读，守卫未误伤；死锁修复保证即便折叠驱逐了内容也能重读（本跑未触发折叠故未涉及，单测已覆盖）。 |
| **健壮性守卫（stall/forced/nudge/escalation）** | 全 = 0，`interventions=0` | 追得顺时守卫**静默不插手**——证明它们是"兜底"而非"常态开销"；只有卡住/发散才触发（本跑没卡）。 |
| **O(1) 收尾** | `conclusion=1`，8 步就收尾 | 链路图由累积的 hops 直接渲染，不在大上下文里重推。 |

## 这道演练说明了什么
- **记忆系统让 35B 在一条 3-4 跳链路上"不发散、不断链、追完必收尾"**：8 步、10k ctx、零介入、结论与 GT 对齐。
- **稳定前缀设计在真实跑中兑现**（缓存均 78%），不是纸面声明。
- **各机制各司其职、且"该静默时静默"**（folded/dedup/stall/forced/interventions 全 0）——正面回应"防过度设计"：兜底机制在顺利跑里零开销，只在需要时才启动。

> 注：这是"顺利"的一跑（temp>0 下同题也有超时/迷路的另一峰，见 §8 消融的多-seed 数据）。本演练证明的是**记忆系统在追得动时能干净地追完**，以及每个机制的作用可在遥测里逐条看见。
