## 0. 一句话结论（修正后的 verdict）

三提议**内核成立、方向对**，字面版不能照单全收——它们都押"知识不足"，而实测与文献一致指向**主瓶颈是行为/流程，不是事实知识**。反直觉点：**rev-agent 已是三个 agent 里硬编码最重的，恰恰这份"重"在深多跳题（EasyNotes）里把它掐死了**。所以正确增量不是"再写死更多流程/加更多硬干预"。

**经红队复审后，把内核收敛成一条可执行铁律：**

> **框架只做两件事——① 按硬可观测事实向上下文注入 context（信息），② 按资源硬上限收 budget。框架永远不替 agent 决定"下一个动作是什么"或"任务是否完成"。**

满足这条，它仍是 agent（rev-agent 的独特价值 = 协议注入 + 深读裁量）；违反这条，它退化成 zinja 那类反编译流水线，独特价值丢失。四条落地推论：

- **保留并深化"卸载型"结构**（协议 prompt、台账、grep-first 工具）——被 pi 实测验证的核心；
- **软化强制干预**：守卫默认动作从"计数触发的强制收尾"改成"信号触发的注入 CHECKPOINT + 自适应预算"；终止权只在真正墙钟/token 硬上限时收回，且**明确标注为资源上限而非"任务判定完成"**；
- **知识按硬事实注入、只作 context 不作 control**：窄化到"程序性 playbook（做法）"+"强模型前置案卷（corpus）"，不做通用事实 RAG；且优先投 corpus/advisor（bitter-lesson 安全），playbook 库降到最后、最小、仅自动生长；
- **上限如实讲**：全混淆无锚点（Device_Info）是模型+keyword-grep 联合上限，任何流程编排救不了；而真正能破壁的动态分析（frida/脱壳-dump）**今天的 harness 结构上还做不了**（shell 一次性、无 stdin），于是现实中唯一可落地的破壁通道只剩强模型 case-file——这把重量又压回"advisor 才是最该花钱的地方"。

## 1. 把三条模糊提议精确化成可实现机制

用户三提议是"意图"层面的，先落到**五个实现层**才能分别评估：① 系统提示(prompt) ② 编排状态机(orchestration/loop) ③ 外挂事实知识库(fact-RAG) ④ 程序性 playbook 工具(procedural-RAG) ⑤ 强制干预守卫(guards)。

| 用户原话 | 字面读法 | 精确化后落在哪层 | rev-agent 现状（实读代码核实） |
|---|---|---|---|
| **提议1** "把逆向经验/套路做成外挂知识库/文档，或编排里写死更多流程，减少每步让模型自行抉择" | 堆知识库 + 写死流程 | 拆两半：**流程→①②**（高杠杆），**知识→③(低)/④(中)** | §1-§9 协议 prompt 已写死 7 铁律/4 阶段/意图→工作流映射（`docs-resources/LLM首轮注入prompt.md`，`src/prompts.ts:45-74`）；stack-probe 栈指纹库（`src/stack-probe.ts:64-109`）；tool-help 13 工具被动库 |
| **提议2** "在 Agent Loop 里强制干预，明确告知下一步动作" | 强制下一步 | **⑤ 守卫层**（最危险的字面版） | 已落地 6+ 种守卫：stall/readHopStall/exploration-nudge/enoughHops/noInvestigate/continuation（`src/agent.ts:583-810`），forcedFinish 硬禁工具（`:881-900`） |
| **提议3** "内置多范式/经验，遇困先搜知识库方法，再尝试更多方案" | 检索方法库 | **④ playbook + 遇困检索**（内核好，需防"弱模型不会检索"悖论） | ledger 结构化记忆（`src/memory/ledger.ts`）；stuckIntervene + 云端 advisor（`src/agent.ts:524-560` + `src/advisor.ts`）；唯一硬编码备选范式=正向追不动→反向追踪 |

**精确化后的三条可实现机制（已按红队收紧）：**

- **提议1 精确版**：`①②` 编码**工具无关的行为纪律**——但红队把"工具无关"进一步钉死为判据（见 §7 挑战1）：**凡关于"我该怎么查"（grep 先行 / read≤200 行 / 拿到 file:line 收尾 / 缺源码树 fail-fast）可以写死，凡关于"目标长什么样"（见到 X 壳→走这 3 步）绝不能写死**。`③` 通用事实 RAG——弱杠杆、慎做；`④` 程序性套路库——中杠杆、值得做但策展成本高、且必须自动生长。
- **提议2 精确版**：保留**粗粒度强制转移**（侦察先于 read、grep 先于结论），但守卫的**默认动作改为"注入信息 + 扩预算"，不是"删除选项/强制收尾"**。触发从"步数/墙钟无增长"（count-gated）改成"证据质量/是否逼近锚点"（signal-gated）。
- **提议3 精确版**：`④` 按需检索"做法"可行且低风险；但必须由**系统按探到的栈（硬事实）主动注入**，不能靠弱模型自己想到去查（悖论见 §2/§7）；且注入的是 **context 不是 control**。"尝试更多方案"必须有界并套同一套信号门控。

## 2. 对齐旧裁决（行为 vs 知识 ≈ 11:1）与新证据

### 2.1 旧裁决核心

旧裁决（`arch_three_proposals_verdict`）：三提议字面版全否；内核选择性做 P0/P1/P2；核心=**"三者都押'知识不足'，但主瓶颈是行为（约 11/12）不是知识（约 1/12）"**。数据依据：v4 benchmark 11/12，唯一知识缺口是 recon-3（不会 aapt2/jadx 两跳子命令语法），其余失败均为行为型（过早终止/grep 策略差/不写最终答案）。注：11:1 是**特征化比例**不是精确统计。

### 2.2 四条新证据分别支持/修正了旧裁决的哪一条

| 新证据（2026-07-12 实测） | 对旧裁决的作用 | 结论 |
|---|---|---|
| **pi-agent 默认提示→超时空答；仅注入"RE 纪律"系统提示→翻转命中全部 GT** | 强力印证"瓶颈是行为"，并**向上修正权重**：一段话纪律把"总失败"翻成"命中 GT" | 行为/流程编码从"选择性做"**升格为主杠杆** |
| **rev-agent 焊死协议+守卫→定点定位快 3.5x/省 4x；但 EasyNotes 深多跳时守卫 reads=0/step8 提前掐停→浅答；无守卫的 pi 反而读 15 文件跟到真破解点** | **新增旧裁决没有的限定**：强制干预是双刃剑，过度硬编码切断合理深调查 | **直接反对提议1/2 字面版** |
| **case-file（强模型去混淆映射+候选 file:line+待核对清单）喂 pi 续跑→"搜索题"降级成"照线索核对题"，pi 6.8x 快命中** | 旧裁决以为三提议"碰不动真上限"，但一种知识侧干预能**搬动**上限 | corpus/case-file 路径**被旧裁决低估，值得加码**（措辞见 §7 挑战5：搬动≠突破） |
| **全混淆无 grep 锚点（Device_Info）：pi 与 rev-agent 单跑都打不动** | 印证并细化旧裁决"三提议都不碰真正 blocker" | 上限是模型+keyword-grep 天花板，**非 harness 的锅**——但红队补：另有一块天花板确实是 harness（无动态能力，见 §7 挑战5） |

### 2.3 文献如何裁定"行为 vs 知识"（不是二元，按类型分）

一手来源给出更精细判据——**不是"scaffold 好/坏"，而是按类型分**：

- **卸载型 scaffold（把工作从模型拿走：外部状态/台账、强制纪律、检索到的领域知识、设计好的工具接口）可靠有益，且对弱模型收益更大。**
  - NVIDIA《SLM are the Future of Agentic AI》 https://arxiv.org/abs/2506.02153 ：让 code/orchestration 掌控 control flow，模型只做被紧约束的小步——本命理论靠山。
  - StateFlow https://arxiv.org/abs/2403.11322 ：把决策权从模型移给状态机，在弱模型 GPT-3.5 上成功率 63.73% vs ReAct 50.68%、成本降 4-6x——直接的弱模型正面证据。
  - Confucius Code Agent https://arxiv.org/abs/2512.10398 ：Sonnet 4.5+CCA scaffold 52.7% 胜过 Opus 4.5+官方 scaffold 52.0%——"弱模型+好 scaffold > 强模型"。
  - CRAKEN（CTF 含逆向）https://arxiv.org/abs/2505.17107 ：注入安全知识库，弱模型受益更多、强模型收益递减。
  - Anything2Skill https://arxiv.org/abs/2606.09316 ：skills 单独 82.3% > fact-RAG 单独 76.5%，组合 94.1%——程序性(做法)知识独立于事实检索也有价值。
- **"想更多"型 scaffold（要弱模型做更多内部推理：长 free-form CoT/规划）可能反噬。**
  - Wei et al. CoT https://arxiv.org/abs/2201.11903 ：CoT 是涌现能力，只在 ~100B+ 才有益，小模型产出不合逻辑的链、比标准 prompt 更差。→ 对 35B 应推"卸载型"结构，别加"想更努力"结构。

### 2.4 诚实结论：哪些内核有力、哪些要小心

**内核有力（放心做）：**
- 提议1/2 的"行为/流程编码"内核——文献五路（Anthropic / AlphaCodium / MetaGPT / NVIDIA-SLM / StateFlow / LangGraph）+ pi 实测一致背书。
- 提议3 的"程序性 playbook"内核——AWM(Mind2Web +24.6% / WebArena +51.1% 相对提升且步数更少 https://arxiv.org/abs/2409.07429 )、Voyager、ExpeL、CBR。

**要小心（有明确失败标签）：**
- **纯事实 RAG 的弱模型检索悖论**：仅 1/12 是知识缺口；无现成机器可读"破解套路"库；更致命的是**弱模型往往不会主动检索**——`grep 'tool-help' src/` **零命中**（红队坐实），全靠模型自己想到去查，等于没有。→ 知识库必须系统主动注入。
- **硬编码流程的脆性/过拟合**：Blueprint-First https://arxiv.org/abs/2508.02721 自陈须人工穷举全部状态转移、开放域不 scale；leehanchung/hugobowne/lowtouch.ai 一致：RAG 管线、planner-executor、tool wrappers、vector-memory 都被新模型吸收，harness 优势 model-specific 易脆断。→ 每条硬编码规则必须可 feature-flag、可移除。
- **强制干预切断深调查**：《Is Your Agent Playing Dead?》 https://arxiv.org/abs/2606.14831 ：护栏把"诚实完成"逼成不可满足状态时，弱模型会编造/伪装收尾。《Thinking vs Doing》 https://arxiv.org/abs/2506.07976 ：深多跳的胜利来自 test-time 交互/回溯深度，硬 forced-finish 把这条轴砍掉了。

## 3. 落地设计（分层方案，已并入红队修正）

### 3a. 流程/范式编码进 prompt 或轻状态机 —— 低成本、高杠杆、已被 RE 纪律实测验证

**做什么**：继续走 MetaGPT 式 SOP 编码，但只焊死**工具无关的不变纪律**，不焊死目标特定步骤脚本。

- §1-§9 是这层主载体，方向正确，**保留**。
- pi 那段"RE 纪律"（grep 先行 / ≤200 行 read / 拿到 file:line 收尾 / 别乱翻）等价于一个一段话 skill，是决定性设置。
- **成本约束**：SWA 稳定前缀铁律要求 system 逐字节静态（`src/agent.ts:306-322`）。往 system 头部塞更多写死内容不是零成本——头部越长 prefill 越贵。"再写死更多"边际递减，应克制。

**红队修正（挑战1）——钉死可写死/不可写死的判据，并解决 3a 与 4.1 的自相矛盾：**

> 判据：**凡是关于"我该怎么查"（分析者行为不变量）的可以写死；凡是关于"目标长什么样"（制品结构假设）的绝不能写死。** 纪律能泛化，因为它对 target topology 不变；步骤脆断，因为它把 topology 假设烤进了 control flow。

由此**收紧轻状态机**：状态机的边**只能由可观测的制品事实**（stack-probe 探到的字符串、文件是否存在）决定，**不能由推断的任务状态**（模型"看起来卡了"）决定。前者事实驱动、可证伪、脆性低；后者启发式驱动、会误判、本身就是脆性。可预测性来自"事实条件边 + 证据退出 gate"，不是硬步数、更不是"看起来卡了"的启发式分支。

**不做**：把 agent 退化成固定线性脚本（见 §4）。

### 3b. Playbook / 套路库（程序性知识，遇困检索"做法"而非"事实"）—— 中杠杆，但按红队降级为"最后、最小、仅自动生长"

**做什么**：建一个**场景→套路**的程序性 playbook 库（不是事实库）。形态参考：
- Anthropic Agent Skills（渐进披露 Discovery→Activation→Execution，按需加载）——检索/匹配触发的引导，而非总是开火的守卫。
- Quark-engine 的 JSON 规则形态（crime=action+target, score, label）是好的编码模板。
- ExpeL https://arxiv.org/abs/2308.10144 ：不只存成功套路，还把失败挖成 do/don't 洞见（如"没跑 stack-probe 前不许断言无 native"）。

**关键：避免弱模型不会检索的悖论——但红队指出草稿的"主动注入"藏了 §3d 同一只角（挑战2+3 合流）：**

"系统决定何时注入"本身就是一次决策，若靠"模型好像卡了"来推，它就变成了挑战3 禁止的"规则引擎替 agent 决定下一步"。故加两道闸：

1. **只由硬可观测事实触发**：stack-probe **确凿匹配**到 "360 加固"指纹字符串 → 注入对应 playbook 到 messages 末尾（遵守 SWA，不进 system 头部）。**不可以**："模型连续 3 步没进展"→ 猜它需要某 playbook 推给它（那是把挑战3 的病伪装成挑战2 的药）。
2. **只作 context 不作 control**：playbook 作为"可参考的做法"拼进上下文，模型仍可无视；绝不能变成"检测到 X 就强制执行 Y 步"——一旦如此，知识库退化成硬编码流水线，挑战1 全部反噬。

**升级路径（超越手写）**：Voyager/AWM/CBR-Retain 都从 agent 自己解出的轨迹里归纳 playbook。rev-agent 已有 ledger + --corpus，可自动把解出的 APK 案例挖成 embedding 索引的成长型库。**红队定调：手写策展基本别做，只做"从解出轨迹自动生长"那版**（理由见 §4.2 bitter-lesson 半衰期）。

**别做**：通用事实逆向知识库；把 200+ 工具的 MCP 面（GhidraMCP/revula）全塞给 256K 模型——上下文塞不下 + lemonade 单并发要求工具调用串行。

### 3c. 前置案卷 / 强模型 handoff —— 已有 --corpus，被旧裁决低估，红队进一步提前到第二优先

**做什么**：攻**真上限**的唯一可落地路径，已是 rev-agent 的 `src/corpus.ts`（11216B）+ 在线版 `src/advisor.ts`。

- PEAR https://arxiv.org/abs/2510.07505 给判据："弱规划器对性能的拖累远比弱执行器严重"，强规划器能补偿弱执行器，规划只占约 20% token → "强模型做规划/案卷 + 弱本地模型做执行"是便宜且高杠杆的组合。但校准预期：分离主要买**成本与可控**，不是把弱模型上限抬到强模型。
- 去混淆文献 https://arxiv.org/abs/2604.08083 证明上限是真的：控制流平坦化/虚假控制流各让反编译成功率降 >70%。

**红队修正（挑战5）——措辞从"破天花板"收敛到"搬天花板"**：case-file 不消除天花板，只把它从"本地 35B + grep"**搬到**"强模型的去混淆能力 + handoff 保真度"，代价是引入 PEAR 承认的新失效模式（案卷一错，弱执行器盲信、整条跑偏）。所以它是"更高的地板 + 可控成本"，不是"破天花板"。

**扩展方向**：
- 案卷必须给**真去混淆 file:line 锚点**，不能是泛泛散文（`src/advisor.ts` 的 fail-closed 脱敏门是对的）。
- 执行阶段须保留**质疑与 replan** 能力：前置案卷一旦错，下游整条跑偏（PEAR：攻击规划器最有效）。别让弱执行器盲信案卷。

### 3d. 强制干预的"软硬度"调参 —— rev-agent 双刃剑的直接修复（本轮最高优先增量）

**病根在代码里可定位**：stall 用 `stallCap`（默认 3 步无 reads+greps+hops 增长，`agent.ts:236`）、readHopStall 用 `readHopStallCap`（默认 5 步只 grep，`agent.ts:237`）触发于 `:590`/`:623`，判据是**墙钟/步数无进展**而非**证据质量**；`forcedFinish` 硬禁工具（`:881-900`）。EasyNotes 深多跳没能立刻 +1 read/hop 时被判空转、reads=0 叠加 noInvestigate，逼出浅答。

**改法——红队把"count→signal"进一步锐化为"删除选项 vs 增加信息"（挑战3 是真正分界线）：**

真正决定"还算不算 agent"的不是"计数 vs 信号"，而是**干预是「删除选项」还是「增加信息」**：
- **删除选项**（forced finish、硬禁工具）= 流水线。哪怕触发条件从 count 换成 signal，一个"signal-gated 的强制收尾"**仍是规则引擎替 agent 决定终局**。
- **增加信息**（注入"你已 grep 5 次未读新代码，当前假设是什么？下一条线索在哪？"）+ 调整预算（给活跃线索扩配额）= 仍是 agent，选择权留在模型手里。

据此逐点定性（哪些真解决"还算 agent 吗"）：
1. **AlphaCodium "test anchors"** https://arxiv.org/abs/2401.08500 ：保留已验证进展，只回滚坏迭代——证据条件，不是计数条件。【采纳】
2. **自适应预算**：有活跃线索（新鲜 file:line、未解 xref、正逼近锚点）时扩张 read/step 配额；只在无新证据的原地打转时才 clamp。【采纳，属"增加信息/扩预算"侧】
3. **强制 CHECKPOINT 而非强制 STOP**：把 forced action 改成"必须陈述当前假设 + 下一条线索"，不强制收尾。避开《Playing Dead》编造陷阱。【采纳，是真正的 agent 侧修法】
4. **证据退出 gate 门控"下结论"动作**（如"只有 stack-probe 出过结果才能断言无 native"）：**红队标为双刃**——若实现成"没有 file:line 就硬禁收尾"，它又变回删除选项的规则引擎。【有条件采纳】**修正实现**：把它做成**注入式警告 context**（"你尚无 file:line 锚点，收尾前请复核假设"），而非硬禁工具；模型仍可在标注不确定的前提下收尾。
5. 保留粗粒度强制转移（侦察先于 read、grep 先于结论）——被验证的好干预，不动。【采纳】

**统一原则（挑战2+3 合流的最终形态，已写进 §0）**：守卫默认动作是"注入 + 扩预算"；**终止权只在真正墙钟/token 硬上限时收回，且收回时明确标注"资源上限"而非"任务判定完成"**——后者正是《Playing Dead》诱发编造的那个不可满足约束。

框架已把 interventions 当负向指标度量（`agent.ts:407-423`，"越少越好"），与"介入是双刃剑"自洽——说明"加更多硬干预"设计层面就不免费。

## 4. 防过度设计：哪些别做 + bitter-lesson 半衰期 + 消融/验收

### 4.1 明确别做

| 别做 | 为什么 | 证据 |
|---|---|---|
| **重 RAG 基础设施 / 通用事实逆向知识库** | 仅 1/12 是知识缺口；无现成机器可读破解库；弱模型不会主动检索 | 旧裁决 + tool-help 零命中 + Anything2Skill(skills>fact-RAG) |
| **把 agent 退化成写死线性脚本、剥夺深读裁量** | 正是 EasyNotes 判错主因；开放域不 scale | pi vs rev-agent 对比 + Blueprint-First + leehanchung |
| **状态机的边由"推断的任务状态"分支** | 那是脆性本身；违反挑战1 判据 | 红队挑战1（§7） |
| **给不会检索的弱模型堆知识库然后指望它自查** | tool-help 的活教训 | `grep 'tool-help' src/` 零命中 |
| **任何"检测到 X 就强制执行 Y 步"的注入（control 而非 context）** | 退化成硬编码流水线，丢掉 agent 价值 | 红队挑战2+3（§7） |
| **再加硬阈值守卫 / signal-gated 的强制收尾** | 硬护栏诱发编造；signal-gated 的强制收尾仍是规则引擎 | `agent.ts:583-643` + arXiv 2606.14831 + 红队挑战3 |
| **手工策展 playbook 库当主投入** | 建造成本高 × 被更强模型淘汰概率高 = 后悔度最高（见 4.2） | 红队挑战4 |
| **为已过工具前沿的目标（全混淆无锚点）继续加固 loop** | 模型+grep 联合上限，流程编排救不了 | Device_Info 双失败 + arXiv 2604.08083 |

### 4.2 bitter-lesson 半衰期——从"卫生"升级为"投资决策"（红队挑战4）

草稿的"每条规则可 feature-flag + 离线 eval + leehanchung 座右铭"是**卫生措施，不是投资决策**——它让你日后能删，却没告诉你现在该不该建。bitter-lesson 的咬法是**不均匀**的，应按 **(建造成本 × 被淘汰概率)** 排序投资：

| scaffold 类型 | 建造成本 | 被更强模型淘汰概率 | 后悔度 | 该不该现在做 |
|---|---|---|---|---|
| 纪律 prompt / 信号退出 gate | 低(一段话) | 高(强模型自带纪律) | **低**(删起来一行) | 做，首选 |
| 云端 advisor / 强模型 case-file | 低(调 API) | **零**(它买的就是前沿能力，前沿变强它免费变强) | **零** | 做，加码 |
| 手工策展 playbook 库 + embedding 索引 | **高**(策展+维护) | **高**(强模型第一个让它冗余) | **最高** | 最后，且只做自动生长版 |

结论：**钱应优先花在 advisor/case-file 通道（§3c），而不是 playbook 库（§3b）**。云端 advisor 是 bitter-lesson **安全**的花法（能力外包给前沿，每次迭代白嫖）；手工 playbook 是 bitter-lesson **暴露**的花法（每分策展工都在赌 35B 不被换掉）。这直接改写草稿的排序——corpus 提到守卫改造之后的第二位（甚至并列第一），手写策展基本别做。

保留的卫生措施（必要但不充分）：每条硬编码规则可 feature-flag + 可移除；维护离线 eval 套件，检测"某条帮了 Qwen3.6-35B 的规则哪天开始伤害下一个 70B"。座右铭（leehanchung）："为你手上的算力加结构，然后移除它，因为结构会成为下一档算力的瓶颈。"

### 4.3 消融/验收思路

- **A/B 消融**：同一题库，逐条开关 §9 各铺垫、每种守卫、每个 playbook 注入，看命中率 + interventions 计数 + 工具数 + 墙钟。（复用 `emitScorecard`。）
- **守卫改造验收（3d 的核心回归，双向）**：EasyNotes 类深多跳题，signal-gated + CHECKPOINT 应把 reads=0 浅答翻成"肯深读→命中真破解点"；同时中难度定点定位题**不能退化**（快 3.5x/省 4x 的优势要守住）。防"松了守卫→退回发散"。
- **注入是 context 非 control 的验收**：断言在任何注入触发下模型仍有"忽略该注入并继续"的可执行路径（无工具被硬禁）；终止只发生在资源硬上限且日志标注为"资源上限"。
- **playbook 检索验收**：注入相关 playbook 的题命中率+步数应优于不注入；且不会在无关题上因误注入变差。
- **上限如实标注**：全混淆无锚点题作为"已知天花板"单列，不计入 harness 回归。

## 5. 分阶段 MVP（最小可行、可独立验收、按 bitter-lesson 半衰期重排）

> 铁律遵守：lemonade 单并发→所有本地模型调用串行；每轮结果落盘 md + commit。
> 相对草稿的重排（红队挑战4/5 驱动）：corpus/advisor 从"中段"提到守卫改造紧后的第二优先；手写 playbook 库降到全列最后、最小、仅自动生长；事实 RAG 不在列。

### MVP-0（离线、零本地模型调用，先做）：守卫改造的**离线单测地基**
- 为 stall/readHopStall 写**纯函数化触发判据 + 离线单测**：喂造好的 (reads, greps, hops, 有无新 file:line/xref) 序列，断言 signal-gated 版本在"有活跃线索"时不掐停、在"原地打转"时才 clamp（clamp = 缩预算，不是强制收尾）。
- 独立验收：单测全绿，不跑模型。**最高优先、风险最低、当天可开工。**

### MVP-1（1 次串行复测）：count-gated → signal-gated + forced-CHECKPOINT + 资源上限才终止
- 实现 §3d 的 1/2/3/5，feature-flag 包裹（`REV_GUARD_MODE=signal|count`）；§3d-4 做成注入式警告而非硬禁工具；`forcedFinish` 仅在墙钟/token 硬上限触发且日志标注"资源上限"。
- 独立验收：EasyNotes 深多跳从"reads=0 浅答"翻成"深读命中"；中难度定点定位命中率/速度不退化；模型在任何注入下仍可继续（无工具被硬禁）。产 6 要素结构化 MD 对比 v(count) vs v(signal)。

### MVP-2（--corpus 深化，bitter-lesson 安全，提前到第二优先）：case-file handoff 扩展
- 强化 `src/corpus.ts`/`src/advisor.ts`：确保案卷给真 file:line 锚点、执行阶段保留 replan/质疑、fail-closed 脱敏门守住。
- 独立验收：全混淆题在"有前置案卷"下从空答→照线索核对命中（复现 pi 的 6.8x 结果）；无案卷时如实 fail-fast 不硬撑；案卷注入错误锚点时下游能质疑而非盲信（注入一条"错锚点"探针题验证 replan）。

### MVP-3（离线为主）：tool-help 从被动→主动注入（只由硬事实触发、只作 context）
- 框架按 stack-probe **确凿匹配**到的栈，自动把相关工具片段拼到 messages 末尾（遵守 SWA），不再靠模型 grep；注入是 context，模型可无视。
- 独立验收：recon-3 类"两跳子命令语法"题不再需要模型自己想起来查；A/B 命中率对比；确认无"检测到栈→强制执行某步"的 control 语义。

### MVP-4（策展从简 + 1 次复测）：第一个程序性 playbook，仅自动生长优先
- 优先走 §3b 自动生长路径：从 ledger/--corpus 解出的轨迹自动挖 1-2 个套路，embedding 索引，硬事实匹配触发注入。手写策展仅作冷启动兜底，最小化。
- 独立验收：匹配题命中率↑、步数↓；无关题不退化。

**排序（高→低杠杆，已按 bitter-lesson 半衰期）**：MVP-0/1（守卫改造，治 EasyNotes 回归，便宜+可逆+修代码坐实的回归）> **MVP-2（corpus/advisor，攻/搬上限，bitter-lesson 安全的花钱处）** > MVP-3（tool-help 主动注入）> MVP-4（playbook，最后、最小、仅自动生长）。事实 RAG 不在列。

## 7. 红队复审与修正（逐条采纳/驳回）

总基调：草稿本身已是红队过一轮的稿子，5 条里预判了 4 条。红队攻的是"让步得还不够/修法自身有洞"。**5 条挑战全部采纳成立**，但其中挑战 2、3 实为同一只角，草稿分开修埋了矛盾；挑战 4 草稿的修法必要而不触要害；挑战 5 草稿略高估 case-file 且漏了 harness I/O 一块天花板。

### 挑战 1：硬编码流程脆性 —— **采纳（部分）**，把软口号钉成硬判据
- **采纳**：草稿 §4 已认脆性，但"只焊死工具无关的不变纪律"是软口号，可操作性不足。已并入 §3a 的锐化判据：**"我该怎么查"可写死 / "目标长什么样"绝不能写死**（对 target topology 不变才泛化）。
- **采纳并修自相矛盾**：红队发现草稿 §3a 的"conditional edge 状态机"与 §4.1"别写死流程"打架——conditional edge 就是按目标状态分支。已修：**状态机的边只能由可观测制品事实（stack-probe 字符串/文件存在性）决定，不能由推断任务状态（"看起来卡了"）决定**。前者可证伪脆性低，后者启发式就是脆性本身。写入 §3a、§4.1。

### 挑战 2：弱模型检索悖论 —— **采纳（最硬一条，代码坐实）**，且与挑战 3 合并解
- **采纳**：`grep tool-help src/` 零命中当场坐实，草稿也认。
- **修法有洞（并入合并解）**：草稿"系统主动注入"藏了"谁决定何时注入"这次决策——若按"模型好像卡了"推，就变成挑战 3 的规则引擎。已加两道闸并入 §3b：**① 只由硬可观测事实触发（stack-probe 确凿匹配），不由推断状态触发；② 只作 context 不作 control（模型可无视，绝不"检测到 X 就强制执行 Y 步"）**。

### 挑战 3：谁决定下一步 / 还算 agent 吗 —— **采纳（本轮最该重视）**，真正分界线是"删除选项 vs 增加信息"
- **采纳**：守卫 count-gated（`:236-237`）、`forcedFinish` 硬禁工具（`:881-900`）代码坐实，"切断合理深调查"是当前实现的确定行为，非推测。
- **修法锐化**：草稿 count→signal 方向对但没抓住真判据。真判据不是"计数 vs 信号"，而是**干预是「删除选项」还是「增加信息」**——一个"signal-gated 的强制收尾"仍是规则引擎。已并入 §3d/§0：守卫默认动作 = 注入 + 扩预算；**终止权只在资源硬上限收回且标注"资源上限"而非"任务完成"**。草稿 §3d-4"证据退出 gate"被标为双刃，改为**注入式警告 context 而非硬禁工具**。
- **合并解（§0 铁律）**：框架只做两件事——按硬事实注入 context、按资源上限收 budget；永不替 agent 决定"下一步是什么/任务是否完成"。

### 挑战 4：bitter-lesson —— **采纳**，从"卫生"升级为"按半衰期排序投资"
- **采纳**：草稿 §4.2 的 feature-flag+eval 是卫生措施，不回答"现在该不该建"。已并入 §4.2 的 **(建造成本 × 被淘汰概率)** 投资表：advisor/case-file 后悔度=零（bitter-lesson 安全）、手工 playbook 后悔度最高。
- **改排序**：直接改写草稿 MVP 排序——**corpus/advisor 提到守卫改造紧后的第二优先，手写 playbook 降到最后、最小、仅自动生长**（见 §5）。这是本条最实质的落地改动。

### 挑战 5：上限本质 —— **采纳**，两处修正
- **采纳并收敛措辞**：case-file 不"破"天花板只"搬"天花板（从"本地 35B+grep"搬到"强模型去混淆+handoff 保真度"），且引入案卷错误→弱执行器盲信的新失效模式。已改 §3c/§6 措辞，并在 MVP-2 加"错锚点探针题验证 replan"。
- **采纳（草稿漏的）**：天花板有一块是 **harness I/O 限制非模型限制**——动态分析（frida/脱壳-dump）因 shell 一次性、无 stdin 进不了 loop（completeness_audit 早指出）。已补入 §6 天花板段与 §0：真正能破壁的动态路今天结构上做不了，于是唯一可落地破壁通道只剩强模型 case-file——与挑战 4 收敛到同一结论（advisor 最该花钱）。

**无驳回条目**：5 条全部采纳；争议点均为"草稿修法有洞/让步不够"，已按红队修正并入正文，未发现红队本身的过度主张需要驳回。

## 8. 结尾 Verdict（与修正后设计一致）

三提议内核成立，字面版否。经红队复审，把内核收敛为一条铁律：**框架只按硬可观测事实注入 context、按资源硬上限收 budget，永不替 agent 决定"下一步动作"或"任务是否完成"**。满足此线它仍是 agent（协议注入 + 深读裁量是 rev-agent 唯一价值）；越线即退化成反编译流水线。
