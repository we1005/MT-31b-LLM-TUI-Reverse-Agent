## 2. 数据格式

### 2.1 题库 bank（judge = `scripts/score-anchors.py`）
两种 schema，判分器都吃：
```jsonc
// bank-multi 式(CTF/理解题):
{ "problems": [ { "id": "...", "difficulty": "medium|hard", "workdir": "<jadx>",
  "task": "<题面>", "ground_truth": "<GT 文本,含 file:line + 类/方法>", "evidence": "<锚点>", "grading_regex": "C19184|..." } ] }
// bank-crack 式(破解审计题):
[ { "id": "...", "crack_point": "<类.方法+行>", "chain": "<调用链>", "grade_keywords": ["...","..."] } ]
```
判分：从 GT 文本抽"证据锚点"(`file:line` + 驼峰/含$类名 + `方法()`)，数它们在 agent 输出 `<id>.out` 里的**召回率(recall)**。绝对值有噪声，**相对 Δ 可复现可比**（消融/AB 用）。
用法：`python3 scripts/score-anchors.py <bank.json> <results_dir> [out.json]` → 产 `_anchors.json` 记分卡。样例题库见 `scratchpad/pi-bench/bank-pi.json`；样例 GT 见 `pi/GT-easynotes.md`。

### 2.2 SCORECARD（rev-agent 每次收尾 emit 一行 warn → stderr）
```
[SCORECARD] steps=N ledger(hops=H ✓C reads=R greps=G) cache_avg=X% cache_min=Y% max_ctx=M folded=F dedup=D
            nudges=N2 checkpoints=CP guard=signal|count explore_nudges=EN stall=0|1 forced=0|1
            escalations=E wrap=0|1 conclusion=0|1 interventions=I
```
逐字段对应组件（台账/前缀缓存/ctx控制/断链防护/止损/守卫模式/收尾/介入次数）。`interventions` 越少越顺。`guard` 是本轮守卫模式(框架化)。抓法：`grep -a 'SCORECARD' <run>.err | tail -1`。
`--once` 完成另有 `✓ done (steps=.. budget=<输出token>)`；budget 只计**输出 token**(线性诚实)，与 pi 的 totalTokens(含 prefill+cache) **口径不同不可直接比**，跨 harness 比用**墙钟 + 工具调用数 + 命中**。

### 2.3 pi 会话 session.jsonl（`~/.pi/agent/sessions/<enc-cwd>/*.jsonl`）
逐行 JSON。关键：`type=="message"` 行的 `message.usage{input,output,cacheRead,cacheWrite,reasoning,totalTokens}` 与 `message.content[]`（`type` ∈ `text|thinking|toolCall`；`toolCall = {type,id,name,arguments}`）。`enc-cwd` = 绝对路径把 `/`→`-`、首尾加 `--`。解析器见 `pi/run-pi.sh` 内嵌 python。

### 2.4 ledger 台账（`ledger.toJSON()` / agent 每步 render 到 messages 末尾）
```jsonc
{ "goal": "<首条任务 verbatim>",
  "hops": [ { "raw": "A.x → B.y | 证据 F.java:12", "from": "A.x", "to": "B.y", "evidence": "F.java:12", "corroborated": true } ],
  "reads": [ { "path": "...", "ranges": [ { "start": 1, "end": 200, "evicted": false } ] } ],
  "greps": [ { "pattern": "checkVip", "path": ".", "hitCount": 3 } ] }
```
只记导航元数据 + 调用边；**不记语义发现**（见 `顺路发现缓存` 待办）。

### 2.5 脱敏占位符（`redact.ts`）与云端顾问案卷
- 占位符：`<CLS_n>/<PKG_n>/<PATH_n>/<SYM_n>/<URL_n>/<IP_n>/<EMAIL_n>/<KEY_n>/<RES_n>`。同真值→同占位符(可逆)；`restore()` 容错还原(裸 id / HTML 转义 / 被揉坏)。fail-closed：`leaks` 非空→不出境。
- 前置强模型案卷 case-file（喂弱模型续跑）：markdown，须含 **①候选破解点(类.方法+file:line 按置信度) ②去混淆映射(短名→真身) ③调用链假设 ④给弱模型的"待核对清单"(read 哪几行确认——把"搜索"降级成"核对")**。样例 `pi/example-casefile-device.md`。

## 3. 一次完整 A/B 复测的标准顺序（串行）
```
1) typecheck(=3) + bun run test(离线全绿)
2) 确认 lemonade 空闲(pgrep) → 才起真实跑
3) 单变量(如 REV_GUARD_MODE=count vs signal) × 多 seed × 分题型(定点/深多跳/审计)
4) 抓 SCORECARD + 命中(score-anchors) + 墙钟 → CSV → 取中位数
5) 结论落 6 要素 md → commit(带 trailer) → push
```
