# 记忆系统·实现交付总结（一页式入口）

> 本文是"针对 256K 本地小模型的上下文记忆系统"的**交付总结**——实现了什么、测了什么、≥20 题验证、消融裁决、具体演练，一处看全。详细设计与消融数据见 [[上下文记忆系统-架构设计]]（§0–§9）；演练见 [[记忆系统-具体题目演练]]。
> 目标（用户设定）：**完全实现 + 无 bug + 测试通过 + ≥20 题验证 + 消融证明每处设计有用（防过度设计）。**

| 带外 Ledger | `src/memory/ledger.ts` | 零-LLM 自动记账（reads/greps/hops）+ 守卫底座 + O(1) 收尾链路图 |

## 2. 无 bug + 测试
`bun run scripts/test-guards.ts` → **30/30 passed**；`tsc --noEmit` 零新增错误（仅 3 个 baseline SDK 类型错，非本次引入）。守卫覆盖：前缀不变、死锁、边派生失败模式（lambda/合成/自边/非标识符/开关）、grep空转、forcedFinish、卡住求助等。

## 3. ≥20 题验证（§8.4）
bank-multi **20 题**（多跳/找类/跨包/安全点/加固）BASE 跑过判分：完成 13 / 超时 7，锚点召回均 0.32（完成题 0.41），3 题高召回（via-02=1.0/modv6-01=0.88/mtmod-02=0.71）。诚实读法：**易/中题追得干净、难题受模型能力上限所限（超时）——记忆系统不改变模型上限，但让追得动的题追得干净**（mtmod-02 靠边派生攒 10 条已核验边）。

## 4. 消融裁决（§8.1–8.5 + §9，诚实不自欺）
| 设计 | 裁决 | 硬证据 |
|---|---|---|
| **台账位置（SWA，拼末尾 vs system）** | ✅ **明确大赢家** | 前缀缓存 **84% vs 47%（+37%）**，duolingo-2 37%→84% |
| Ledger 本体（记账+守卫+O(1)收尾） | ✅ 有用 | 演练自动累积、mtmod-02 ✓hop=10、守卫 30/30 |
| 零-LLM 边派生 | ✅ 情境性有用 + **零空转成本** | 4 题罕触发（✓hop=0）但 mtmod-02 触发 +10 条✓边；6 单测证无错边 |
| 台账渲染给模型看 | ⚠️ **依题净正、非普适** | 5-seed：via-02 +0.5 / np-02 +0.2 / chm-01 平 / modv6-02 −0.2（逐题净 +0.5，池化中位偏 NO_RENDER） |
| 死锁修复 / 前缀守卫 / 判分器 | ✅ 正确性已验证 | 离线单测 |

**总裁决：无一处过度设计（全部零/低成本）；SWA 位置是明确的大赢家；其余机制或正确性关键、或情境性有用且从不有害。** 消融**如实暴露**了"渲染非普适赢、边派生罕触发"——不粉饰，正是防过度设计的目的。

## 5. 具体题目演练（[[记忆系统-具体题目演练]]）
via-01 多跳链路全过程实录：8 步、ledger 自动累积 reads0→4/greps0→3/hops0→2、**前缀缓存全程 66–90%（均 78%）**、`folded/dedup/stall/forced/interventions` 全 0、结论与 GT 对齐（p4.j→p4.a→p4.b 组合迭代→空 WebResourceResponse）、recall 0.70。逐条对上每个机制的实际作用。

## 6. 方法论沉淀（血泪，复用于后续任何测优）
- **单跑聚合 A/B 无效**（temp>0 双峰）：消融必须**同题多 seed 取中位数 + 按题型分指标（定位题看机械召回/栈题看语义）+ 单变量受控**。
- **判分**：确定性机械锚点判分（离线可复现）为主，强模型 rubric 为辅；关键词判分已证失效。
- **后台工程**：bash 后台 waiter 会被环境 kill，长等改用**前台阻塞轮询**（timeout 570s）；孤儿 bun 子进程会占 lemonade，父进程死后要清；lemonade **单并发**必须串行。

## 7. 后续可选提纯（非必需，有触发条件才做）
- 渲染提纯：试"仅在 ≥N 跳时才渲染台账"（因 modv6-02 上略伤，疑台账占注意力）。
- 边派生扩产：加最小 tree-sitter 或 smali `.method` 回扫，提高触发率（当前极保守罕触发）。
- 若实测 body 常驻 >50K / 折叠频繁 → 再实现 2b-2 写入即落盘。
