# rev-agent 上下文记忆系统 · 架构设计（针对 128K 小模型）

> **日期**：2026-07-11
> **动机**：用户指正——128K 小模型上下文是最稀缺资源，必须有**系统性记忆系统**（像 Claude Code/OpenHands），不是零散补丁。之前的 compactHistory/nudge/exploreCap/enoughHops/hopCount 是散补丁，本设计把它们**收编**成一个内聚子系统。
> **方法**：workflow 综合 OpenHands Condenser / Claude Code 5层 / Hermes 三级阶梯 / MemGPT 分层，首席架构师按 curation>volume **裁剪掉近一半过度设计**。
> **调研依据**：`convergence_optimization_loop.md` + workflow wf_f2bac60c(记忆机制调研)/wf_0bffd29c(本架构)。

---

## 0. 核心判断（裁剪原则）

三家成熟 agent 的共同真相：**丢出上下文 ≠ 从磁盘删除；压缩=可逆 view 变换，底层真相全留**。rev-agent 现在犯了唯一大家都不犯的错——**丢了不可恢复**（compactHistory 破坏式 mutate）。

**关键裁剪**（curation>volume 用在架构本身）：
- 日志**直接就是 append-only 的 `ModelMessage[]`**（v6 原生形状），**不搞自定义 Event 类型**——因为 v6 tool-call↔result 配对是 #1 致命风险，多一层翻译多一倍出错面。
- 折叠只把 tool-result 的 `output.value` 换成 stub、**绝不删消息**，配对天然保住。
- **逆向巧合**：被折叠的类体本就在反编译产物磁盘上 → stub 存"文件路径+行范围"指针，模型用现成 read_file 重取，零额外存储。

## 1. 分层架构 + 数据流

```
Agent (agent.ts, 瘦身~250行)  传输/审批层
  callLLM(streamText/超时/重试/流式emit) · classify→approve→run
  唯一记忆接缝: mem.view() + mem.system()
        │ record*(写)   view()/system()/Directive(读+决策)
ContextManager (memory/context-manager.ts) ★门面/唯一所有者
  持有 HistoryLog + Ledger + Budget + FoldPlan
  写: recordUser/Assistant/ToolCall/ToolResult
  读: view()=投影  system()=base+ledger.render()  contextTokens()
  决策: beforeStep()→Directive / afterAssistant()→Directive
     │                    │                      │
HistoryLog          Ledger                 Budget(几乎不动)
memory/history.ts   memory/ledger.ts       budget.ts
append-only         带外结构化台账          outputTokens累加
ModelMessage[]      (不进messages→          green/yellow/red
=真相,永不改          绕开配对bug,最安全)     降级为纯UI告警
view(foldPlan)      goal/hops/reads/greps
=非破坏投影(mask)    /hyps/deadEnds/next
contextTokens()     observeToolResult(零LLM自动捕)
                    promoteFromProse(正则捞正文跳N)
                    render()→system尾(有界≤1.2k)
                    renderChainGraph()(收尾O(1)拼图)
                    hasRead/hasGrep(去重守卫)
持久化: 磁盘反编译产物(免费日志) + notes.md + ledger.json
```

**数据流（一次 read_file 的旅程）**：
1. LLM 吐 tool-call → classify auto → **dispatch 前查 ledger.hasRead(path,range)**，命中则回"已读过见台账"省 2.5k 充气
2. tools.run 拿 200 行类体 → `mem.recordToolResult` 一处两件事：(a) HistoryLog.append 原文(真相永不改) (b) Ledger.observeToolResult 抽 reads[](verbatim 零LLM)
3. 下一步步首 `mem.view(foldPlan)`：三段式(HEAD 不折 user任务+含跳N/最终结论的assistant / TAIL 不折最近3条 / PREFIX 里这条 mask 成 stub{folded,path,range,reread})，2.5k→30 tok，配对不破
4. `mem.system()` = base + ledger.render()，§reads 里已有"C7671:100-299 已读"→模型不必回翻
5. callLLM: `streamText({ system: mem.system(), messages: mem.view() })` → prefill 稳态 5-10k 而非 173k

## 2. 三个模块（+1 类型文件）

### `src/memory/history.ts` — HistoryLog（真相 + 非破坏投影）
吃掉 Layer1(EventLog+View) + Layer2(mask 档)——对本工具它们是同一个纯函数。
```ts
type FoldPlan = ReadonlySet<string>;              // 被折叠的 toolCallId
class HistoryLog {
  append(m: ModelMessage): void;                   // 唯一写入口,永不改旧消息
  raw(): readonly ModelMessage[];                  // 真相
  view(fold: FoldPlan): ModelMessage[];            // 非破坏投影:新数组,只把被折 tool-result.output→stub
  contextTokens(fold: FoldPlan): number;           // 度量投影(取代 Agent.contextTokens)
  static foldStub(name,value): {folded,tool,path?,range?,hits?,reread};  // 纯函数,可单测
}
// planFold(msgs,{keepRecent,pinnedPredicate})→FoldPlan  三段式纯函数
```
**#1 风险单测锁死**：view(fold) 每个 assistant tool-call part 必须有配对 tool-result part。

### `src/memory/ledger.ts` — Ledger（带外结构化台账，最高杠杆）
**不进 messages → 完全绕开 v6 配对 bug，反而最安全。系统维护，不指望模型自律。**
```ts
class Ledger {
  setGoal(raw): void;                              // verbatim 首条 user
  observeToolResult(name,args,result): void;       // 零LLM: read→reads[], grep→greps[]+候选证据
  promoteFromProse(assistantText): number;         // 正则提升 "跳N:源→目标|证据 file:line"→结构化Hop
  hopCount(): number;                              // 取代脆弱正则计数
  hasRead(path,start,end)/hasGrep(pattern,path): boolean;  // 去重守卫
  render(maxTokens=1200): string;                  // 拼 system 尾,有界
  renderChainGraph(): string;                      // 收尾 O(1) 拼 A.x→B.y→C.z
  toJSON()/fromJSON();                             // resume 水合(比事件回放便宜)
}
```

### `src/memory/context-manager.ts` — ContextManager（门面+决策门）
```ts
type Directive = {kind:'proceed'} | {kind:'inject';reason} | {kind:'finish';reason};
class ContextManager {
  recordUser/recordAssistant/recordToolCallMessages/recordToolResult(写)
  view(): ModelMessage[]; system(): string; contextTokens(): number;  (读)
  beforeStep(): Directive;    // 重算foldPlan + 迷路(exploreCap) + 收尾提醒(enoughHops) + 预检硬止损
  afterAssistant(r): Directive; // 硬止损(ctx>ceiling) + 断链nudge(endsWithContinuationIntent) + done判定
  resetTurn(); snapshot();
}
```

### 重构后 run() 骨架（200行5分支 → 线性）
```ts
async run() {
  while (this.step < maxSteps) {
    this.step++;
    const pre = this.mem.beforeStep();            // 压缩+前置转向
    this.emit('warn', `[ctx=${this.mem.contextTokens()} step=${this.step}]`);
    if (this.apply(pre)) continue;
    const r = await this.callLLM();                // streamText({system:mem.system(), messages:mem.view()})
    this.mem.recordAssistant(r);
    if (r.text) this.emit('assistant', r.text);
    const post = this.mem.afterAssistant(r);
    if (post.kind === 'finish') { this.emit('done', post.reason); return; }
    if (this.apply(post)) continue;
    if (!r.toolCalls?.length) { this.emit('done', r.finishReason); return; }
    this.mem.recordToolCallMessages(r.response?.messages ?? []);
    for (const tc of r.toolCalls) { /* classify→approve→run→mem.recordToolResult */ }
  }
}
```

## 3. 收编计划（散补丁的归宿，删的比加的多）

| 现有补丁 | 归入 | 处置 |
|---------|------|------|
| messages 单一存储 | HistoryLog | 迁移,Agent 不再持有 |
| compactHistory 破坏式 mutate | HistoryLog.view+foldStub | 重写为非破坏投影,原文永留 |
| foldedIds Set | FoldPlan(CtxMgr持有) | 迁移,每步重算 |
| contextTokens | HistoryLog.contextTokens(fold) | 迁移 |
| ctxCeiling 硬止损 | CtxMgr.afterAssistant | 迁移,仍是主止损 |
| nudge/nudgeCount/endsWithContinuationIntent | CtxMgr.afterAssistant | 迁移,判据不动(benchmark验证过) |
| exploreCap/explorationNudged/toolCallTotal | CtxMgr.beforeStep | 迁移,触发改 hopCount()===0 |
| enoughHops/wrapNudged 收尾提醒 | CtxMgr.beforeStep | 迁移,触发改 hopCount()≥阈值 |
| hopWritten/hopCount 脆弱正则 | Ledger.hopCount/promoteFromProse | **删正则,改结构化计数** |

## 4. 分阶段落地（先最高杠杆，各阶段独立合入/回滚）

- **阶段0(半天)立护栏**：用 v6 MockLanguageModelV2+simulateReadableStream 把当前 run() 控制流(断链→nudge→写结论→done)固化成快照测试。之后每步有 A/B 基线。A/B 回放料：memory 旁 `../c0e365ae-*.jsonl` + subagents/*.jsonl 真实 tool-call 序列。
- **阶段1(最高杠杆,先做) Ledger 带外落地**：带外、不碰 messages、零配对风险，直打 run3/Via 真实失败(追对却撞墙重拼、重复读、不自律记台账)。新增 ledger.ts + dispatch 加 observeToolResult + system 拼 render() + read/grep 前 hasRead/hasGrep + hopCount 换结构化 + 收尾用 renderChainGraph。**不比旧版差就合入**。
- **阶段2(中风险,核心正确性) HistoryLog view 拆分**：messages/compactHistory/contextTokens/foldedIds 迁入,compactHistory 改非破坏 view。**必过门**:单测断言 view 配对完整 + ctx 曲线≤旧版。
- **阶段3(低风险,纯重构) ContextManager 门面收口**:转向逻辑收进 beforeStep/afterAssistant,run() 塌成骨架。阶段0 快照测试全绿即无回归。

## 5. 明确砍掉（对 63tok/s/不上云不划算）

1. 自定义 Event[]/SourcePointer/reproducible-only 落指针——省磁盘(免费)不省上下文,却翻倍配对出错面
2. 4档压缩阶梯后3档(prune/tail/summary)——mask 折完稳态 5-10k 远低于阈值,后档几乎不触发;Tier C 本地摘要 63tok/s 纯亏。**只留 mask + enableSummary=false 死接缝**
3. 结构化 append_note 判别联合——35B 易写崩;observeToolResult+promoteFromProse 已填满 ledger
4. shell expand 第4工具——破坏 3+1 工具干净边界,现成 read_file 够
5. 事件级 resume——notes.md + ledger.toJSON 更便宜
6. 不扩张 Budget——已知伪量,别加决策逻辑

**净结果**：3 模块 + 1 类型文件,3+1 工具不变,一个 mask 档 + 一个带外台账 + 一个门面。删的散补丁比新增代码多——这才是 curation>volume 的落地形态。
