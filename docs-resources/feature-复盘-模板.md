# Feature 复盘模板（每改一个大 feature 必填，可回溯）

> 铁律见 memory `feature_review_rule`。逐条用**数据/证据**答，诚实不粉饰；"是否有效"须等**多 seed 复测**（单跑双峰不算数）。复制本模板到 `docs-resources/<feature>-feature复盘.md` 或并入该 feature 的实测文档。

---

## Feature: <名称>（commit / 分支）

| # | 问题 | 回答 |
|---|---|---|
| 1 | **目的** | 要解决什么真问题？（引用触发它的实测缺陷/失败样本） |
| 2 | **期望** | 预期产生什么效果？（可量化则给指标） |
| 3 | **得到** | 实测得到什么？（带数字 / A-B / 多 seed 中位数 / 命中率） |
| 4 | **是否有效** | 达到期望没？证据？（无效就写无效；单跑不算，注明是否多 seed） |
| 5 | **是否必要** | 现有机制是否已覆盖？不做会怎样？ |
| 6 | **是否过度设计** | 更简单做法能否达到同样效果？有没有为复杂而复杂？ |
| 7 | **能挽救 / 能改进修复吗** | 若无效/半效：彻底砍，还是改某处就能救？改哪？ |
| 8 | **裁决** | 保留 / 改进后保留 / 砍掉 / 暂缓 + 下一步 |

**证据链接**：实测文档 / CSV / 单测 / 原始 out。
