# 顺路发现缓存 · 阶段0 闸门实测（双否决 → 不合并）

> 承 memory `findings_cache_verdict`：阶段0 是**一票否决闸门**，两条件都过才认定阶段1(MVP)有价值。目标是「**证伪无害 / 证伪没人用**」，非「证明有用」。
> 分支 `findings-cache`。全程 lemonade 单并发·串行·只读。

## 闸门两条件
1. **Q1 痛点真实吗**：上下文折叠后被重新 grep/read 发现的 token 占比够大吗？（折叠不发生=没痛点）
2. **Q2 小模型真会用吗**：开 `--findings-cache`（append_note 已 un-gate）后，Qwen3.6 真会主动写 note + 线索真被回注复用吗？

## 证据

### Q1（痛点）—— 来自既有埋点（folded/max_ctx），11 个真实 run
| — | 结果 |
|---|------|
| `folded`（折叠触发次数） | **全部 run = 0**（含最大的 kuwo/duolingo/code） |
| `max_ctx` | 5k–28k，峰值 28k **远低于折叠阈 `compactThreshold=160k`** |
| `dedup`（精确重读，已被既有守卫拦截） | 0–4，极少 |

→ **Q1 FAIL**：80k 预算 + SWA 稳定前缀下，真实 RE 任务的 ctx 一直几 k~几十 k，**从不折叠**。既然没东西被折叠出上下文，「折叠后需复原顺路发现」这个痛点**在实测里不存在**。

### Q2（模型会用吗）—— 新增插桩（notes_written/findings_injected），6 个 `--findings-cache` run
| qid | folded | notes_written | findings_injected | max_ctx |
|-----|--------|---------------|-------------------|---------|
| q09-duolingo ×2 | 0 | **0** | 0 | 3.6k/4.7k |
| q05-code ×2 | 0 | **0** | 0 | 4.6k/3.7k |
| q02-easynotes ×2 | 0 | **0** | 0 | 18k/4.4k |
| **合计** | **0** | **0** | **0** | 峰 18k |

→ **Q2 FAIL**：flag 开着、append_note 已 un-gate、还 `--auto-approve`，**Qwen3.6 在 6 个 run 里一次 append_note 都没主动写**。没写 → 缓存永远空 → `findings_injected` 恒 0。弱模型在 --once 自主模式下**根本不自我记笔记**。

## 裁决：双否决 → **findings-cache 不合并**（默认结论兑现）
- Q1、Q2 **都 FAIL**。按闸门「一票否决 + 消融目标是证伪」的设计，这是干净的**证伪**：痛点不存在 + 弱模型不产出可缓存物。
- 与 memory `findings_cache_verdict` 预测**完全一致**（「小模型是否真会写/读回 note」正是 Q2 原话；「效应量在噪声级 + 默认结论倾向不做」）。
- **代码不浪费**：阶段1 MVP 代码正确、离线测 11/11、flag 关零行为变化——作为「已验证证伪」的实验制品留在分支（或删），**不合入 main**。

## 诚实边界（不夸大证伪范围）
- 本测是 **--once 自主模式**。Q2 的「模型不写 note」只证自主模式；**人驱动的 TUI**（用户可手动/指示写 note）+ **跨会话 resume**（note 持久跨重启）没测。
- 但：① 跨会话 resume 正是裁决早已排除的「ledger 落盘/resume 种子重建=镀金」（§3.9），本就不在范围；② 主力自主 --once 工作流已证无需。→ **veto 对自主场景成立，resume 场景本就出局**。
- Q1 的「不折叠」绑定当前设置（budget 80k、compactThreshold 160k）。若将来上极大上下文任务把 ctx 顶到 >160k，痛点可能重现——届时可重开闸门，但那是不同工作负载。

## 处置
- `findings-cache` 分支：**不合 main**。代码 + 阶段0 插桩 + 本实测文档留分支存档；可删可留（不占 main 复杂度）。
- 若将来出现「真会折叠 + 模型真写 note」的工作负载，从本分支复活、重跑阶段0 即可。
