# 如何给 rev-agent 下达逆向任务（使用指南）

> **日期**：2026-07-10
> **回答的问题**：想让 rev-agent 完成"通过逆向摸清 APK 里某个逻辑的链路"这类任务，指令怎么下？TUI 打字，还是把目的写进 Markdown 让它自动读？

---

## 0. 先澄清"静态定位器"——它能做链路追踪

"静态定位器"不是"只能报个类名"。**"摸清 APK 里某逻辑的完整调用链"正是它的主场**，能下指令让它自动做。

"静态"是相对"动态"的边界：

| 类型 | 能否独立做 | 例子 |
|------|-----------|------|
| ✅ **静态代码追踪** | 能，主场 | 追调用链 `onClick → SignUtil.gen → native Java_xxx_gen`、定位某逻辑涉及的所有类/方法、给链路图和逆向方案 |
| ❌ **动态**（须人接管） | 架构做不到 | 跑起 App 点按钮、frida hook 看运行时值、抓 HTTPS 流量——要连真机/交互 |

所以：**你要的"摸清某逻辑链路" = 静态代码追踪 = 它能自动干。**

---

## 1. 三种下达方式

| 方式 | 命令 | 适合 |
|------|------|------|
| **A. TUI 打字** | `bun src/index.tsx`（默认进 TUI） | 探索式、边看边追问、中途想改方向 |
| **B. 目的写进任务串** | `--once "任务..."` | 一次性、可脚本化、目的明确 |
| **C. Markdown 续传** | `--resume --notes 笔记.md` | 从上一会话的**工作笔记**接着干（不是随便一段目的） |

---

## 2. 关键前置：先手动反编译（P0 校验会拦你）

**无论哪种方式，都要先手动反编译好、把源码目录给它。** 因为整包 jadx 要 ~123s，会撞 agent 的 shell 60s 超时——这是刻意的设计（P0 前置校验）。源码级任务缺源码树时，agent 会秒级 fail 并打印配方，不会傻等。

```bash
# 反编 Java 源码（推荐，看逻辑）
jadx --no-res -d /tmp/target-jadx /path/你的.apk
# 或 只解 smali + 资源（更快，改 smali 用）
apktool d -f -o /tmp/target-apkt /path/你的.apk
```

---

## 3. 完整实操（照抄）

```bash
# 第 1 步：手动反编译（一次，约 2 分钟）
jadx --no-res -d /tmp/target-jadx /path/你的.apk

# 第 2 步（方式 B，最直接）：把"摸清哪条链路"写进任务，指向反编译目录
cd /Volumes/zhitai-7100/reverse-agent/rev-agent
bun src/index.tsx --once "在 /tmp/target-jadx/sources 里追出「登录签名」的完整调用链：\
从网络请求拦截器开始，找到签名生成入口方法，一路追到它最终调的 native 方法或加密实现，\
给出每一跳的 类.方法 和证据行，最后画出链路图。" \
  --workdir /tmp/target-jadx/sources --budget 80000
```

### 方式 C 的真相（别误解）

`--resume --notes xxx.md` 读的是**工作笔记格式**（§0 任务/§4 下一步…），是为"续传上一会话"设计的，**不是**"把随便一段目的写文件让它读"。

如果你只是想把长任务描述放文件里：

```bash
# 把目的写在 task.txt，用 shell 读进 --once
bun src/index.tsx --once "$(cat /tmp/task.txt)" --workdir /tmp/target-jadx/sources
```

## 4. 常用参数速查

| 参数 | 作用 |
|------|------|
| `--once "<任务>"` | 非交互单任务，结果走 stdout（不带则进 TUI） |
| `--workdir <目录>` | agent 的工作目录 = 反编译源码树（grep/read 的相对路径基准） |
| `--budget <tokens>` | token 预算上限，默认 80000 |
| `--resume --notes <md>` | 从工作笔记续传 |
| `--verbose` | 用更详细的 §2 长版 system prompt（默认 §1 短版） |
| `--auto-approve` | 自动放行工具（仅 --once 推荐；黑名单仍硬拒） |
| `--backend <name>` | 切后端（默认 lemonade/Qwen3.6） |

注：路径也可以直接写在任务描述里（如"在 /abs/path/sources 里找…"），P0 校验会认任务文本里存在的绝对路径，不一定非要 `--workdir`。

---

## 5. 推荐

- **第一次做某个 APK → 方式 A（TUI）**。逆向是探索性的：它追到一半你可能发现"签名其实在 native"，想让它转向。TUI 能边看**流式思考（💭）+ 工具调用**边追问，比一次性 `--once` 灵活。
- **目的已明确、或要批量/记录 → 方式 B（`--once "..."`）**。

---

## 6. 下指令的措辞技巧（让小模型少跑偏）

结合 §9 避坑纪律，任务描述里说清这几点能显著提升成功率：

1. **给起点**："从网络拦截器 / 从 JNI_OnLoad / 从某个已知类开始"——别让它漫无目的搜。
2. **要证据**："每一跳给出 类.方法 + 证据行"——逼它 read_file 确认，不靠 grep 命中就猜。
3. **要终点形态**："最后画出链路图 / 给相对路径 / 一句话结论"——明确产物。
4. **别一次问太多**：一条链路一个任务，比"把整个 App 逆向一遍"成功率高得多。
