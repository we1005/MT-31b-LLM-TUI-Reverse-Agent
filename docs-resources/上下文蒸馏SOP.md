# 上下文蒸馏 SOP（rev-agent 知识补强的标准流程）

> **日期**：2026-07-10
> **定位**：这是"提议3（蒸馏）"去掉字面错误后的**可执行内核**。**不碰权重、不微调、不 load 新模型、不起 Docker**——那些撞红线#10 + 用户只能用 lemonade 已加载模型。这里做的是【**上下文蒸馏 context distillation**】：dev-time 用强模型把逆向知识提炼成 compact cheat-sheet / skill，通过既有的 §9 自动追加机制喂给本地小模型。
> **依据**：§9 本身就是这么造出来的（3.6KB → 静态定位 3/12 到 11/12）。本 SOP 只是把那次的产法固化成可复用循环。

---

## 0. 什么时候用（触发条件）

**只在遇到「知识类」失败时用**，不要为行为类失败蒸馏：
- ✅ 知识类（该蒸馏）：agent 不知道某工具的 flag/子命令语法、不知道某工作流的正确姿势、不知道某加固/协议的特征。例：recon-3 连试 4 种错误 aapt2 xmltree 语法。
- ❌ 行为类（不该蒸馏，是 loop 机制的活）：过早终止、grep 策略乱、不写最终答案、探索发散。这些占 benchmark 失败的 11/12，蒸馏对它们无效——改 agent.ts 的 nudge/finishReason/重试。

**先自问**：这个失败，是模型"不知道"（知识）还是"知道但没做对"（行为）？只有前者进本流程。

---

## 1. 红线（不可逾越）

| # | 红线 | 为什么 |
|---|------|--------|
| R1 | **绝不把目标 APK 的反编译代码/字符串喂云端强模型** | 撞"逆向数据不上云"红线。只能喂**抽象的通用失败模式**（"agent 不会 aapt2 xmltree 语法"），不能喂"MT2.26.5 的 C11960 源码长这样" |
| R2 | 不 fine-tune / 不改权重 / 不 load 新模型 / 不起 Docker 训练 | 红线#10 + 只能用 lemonade 已加载模型 |
| R3 | 产物是 **少而精、失败驱动**的 cheat-sheet，不是"大量生成" | 数据证明 curation(3.6KB) 赢过体量(12.4KB --help)；"大量"会把信噪比稀释回噪音 |
| R4 | 蒸馏产物不得内置破解/绕过/注入知识 | 只读分析红线；产物只教"分析/定位/识别"，不教"patch/绕过" |

## 2. 五步循环

```
[1] 取样失败      benchmark-models.sh 跑本地 Qwen → 捞失败任务 + trace
       ↓
[2] 分类          只挑「知识类」失败（工具语法/工作流/特征识别），丢掉行为类
       ↓
[3] 抽象          把失败抽象成「通用问题」（不含目标 APK 代码，守 R1）
       ↓
[4] 蒸馏          交云端强模型（volcengine deepseek-v4-pro / kimi）写 ≤4KB 定向块
       ↓
[5] 注入 + A/B    落成 §N 块(extractGuardBlock 追加) 或 skill；复测确认真提升，无回归才保留
```

### 步骤细节

**[1] 取样**：`scripts/benchmark-models.sh`（已存在）跑本地 Qwen3.6，或复用 `<scratchpad>/ctf/run-ctf.sh` + `bank.json`。从 `results/*.err` trace 里找 MISS 的题。

**[2] 分类**：读 trace，判每个 MISS 是知识还是行为（见 §0）。**只留知识类。** 典型知识类信号：agent 反复试错某命令语法、grep 关键词全空但目标确实存在（不是 grep 策略问题而是不知道搜什么词）、把加固/协议特征认错。

**[3] 抽象（守 R1 的关键步）**：把具体失败改写成**不含目标代码**的通用描述。
- ✅ 可喂云端：「安卓 agent 在 macOS 上要用 aapt2 查 AndroidManifest 的树结构，但连试了 `aapt2 dump --xml-text`/`aapt2 dump xmltree --file <apk> Manifest` 等错误语法。正确语法是什么？给一段 ≤400 字的 cheat-sheet。」
- ❌ 不可喂云端：「这是 MT2.26.5 反编译出的 C7671.java，第 76 行 `if(str4==null)`…帮我分析」

**[4] 蒸馏**：让云端强模型输出一块 **≤4KB、markdown、失败驱动**的内容。要求它：只写"正确姿势 + 常见坑 + 一行示例"，不写百科式长文。风格对齐现有 §9（命令 + 一句为什么）。

**[5] 注入 + A/B**：两个落点——
- (a) **常驻**：作为新 §N 块（§11、§12…），改 `src/prompts.ts` 的拼接白名单让它像 §9 一样自动追加到 §1/§2/§3。适合"每次任务都可能用到"的通用知识。
- (b) **按需**：作为 `skill/*.md`，只在相关任务注入（未来 skill 机制）。适合"某类专项任务才用"的知识。
- **A/B 铁律**：注入前后各跑一次相关 benchmark 题。**只有确认目标题 MISS→HIT 且其他题无回归，才保留**。信噪比是生命线——一块没带来提升的蒸馏产物必须删掉，否则稀释 §9。

---

## 3. 产物命名与存放

- 常驻块：`LLM首轮注入prompt.md` 追加 §11+（编号递增，勿改 §1-§10 原文）
- skill：`docs-resources/skills/<topic>.md`（未来）
- 每块开头写：`> 由上下文蒸馏产出（YYYY-MM-DD），针对失败：<一句话>。A/B：<题> MISS→HIT。`
  —— 留证据链，方便日后回收无效块。

---

## 4. 与 P1（tool-help 库）的分工

- **P1 tool-help/**：机械生成的**全量 --help**，agent 现场 grep 查具体 flag。覆盖"语法细节"。
- **P2 蒸馏块**：强模型提炼的**方法论/工作流/坑**，常驻上下文。覆盖"该用哪个工具、怎么组合、有什么坑"。
- 两者互补：tool-help 回答"aapt2 xmltree 的 --file 怎么写"，蒸馏块回答"解 manifest 该用 aapt2 xmltree 而不是 unzip -p"。recon-3 其实两者都能治——P1 让 agent 查到语法，P2 让 agent 一开始就选对工具。

---

## 5. 反模式（别做）

- ❌ 一次生成十几个块囤着——违反 R3，信噪比崩。一次一块，A/B 过了再下一块。
- ❌ 为行为类失败写知识块——治不了，白占上下文。
- ❌ 把 --help 全文塞进 §N——那是 P1 的活，§N 要精炼。
- ❌ 蒸馏时图省事把真实反编译片段贴给云端——踩 R1，最严重。
- ❌ 不做 A/B 直接保留——可能引入回归或纯噪音。
