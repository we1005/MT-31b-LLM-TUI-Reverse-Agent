## 0. 一条决定成败、且本版据此重写设计的代码事实（红队补齐）

已核对源码确认：`agent.ts:308-322` 中，Ledger 的 `render()` **已经**每步作为一条独立 user 消息 `[...this.messages, { role:'user', content: ledgerBlock }]` 拼到 `this.messages` 末尾（spread 不写回持久历史），且注释明写「常驻台账改为『每步临时拼到 messages 末尾』的 ephemeral 消息」。ledger 会话级累积、不每轮重置。

含义：**「每步把增长的台账拼末尾」这套 ephemeral 注入管道已经存在并在跑。** 任何 findings 都不是新建一条注入路径，而是往这条**已在增长的热尾巴**里再塞东西。这条事实改变了草稿几乎每一条风险的力度——很多草稿当成「findings 独有、且被『贴末尾』一笔带过」的风险，其实是既有管道的既有代价，必须正面计量而非回避。

同时确认：
- `note.ts`：`await appendFile(path, block)` —— append_note **已经持久化到磁盘**；schema 正文限「2KB 内」；`classify: () => 'ask'` —— **永远弹审批的硬编码常量**。
- `ledger.ts`：`render(maxChars = 4000)` —— 台账注入**有 4000 字符硬上限**；`toJSON/fromJSON` 存在但全仓零调用（死钩子）。
- `src/corpus.ts` 存在（案卷模式），已确立「出处分级 + 跨源三角验证 + 反幻觉」纪律。

## 1. 问题精确重述

### 1.1 用户想法的精确化

用户原话：agent 在 grep/读代码时会顺路发现「当前用不上、但对后续推理/逆向有帮助」的信息，想先写进数据库/临时文件以便复用，避免重复读取、重复生成、浪费 token。

精确化：

> 在追当前目标（如「定位 sign 生成入口」）的探索路径上，agent 顺手读到的、与当前子目标无关但对后续/未来会话有价值的语义事实（硬编码 AES key、返回 entitlement 的端点、某方法调到 native、某处加壳/混淆），在当前既不被结构化留存也不被主动复用，一旦承载它的 tool 结果被折叠出上下文，就只能靠重 grep + 重读 + 重推理再发现一次。

两个可分离子问题（不可混淆）：
- **子问题 A（防重复读取/搜索）= 导航去重**：同一坐标/pattern 别再跑。
- **子问题 B（防重复推理 / re-derivation）= 语义留存**：那段内容里「有什么语义结论」别再推一遍。

rev-agent 现有系统**几乎完全解决了 A，几乎完全没做 B**（详见 §3）。用户想法的真正落点是 B。

### 1.2 Token 经济学：为什么「折叠即丢」在本场景是硬伤

三个乘数叠加：

1. **超大反编译产物**：jadx/apktool 产物动辄几十万行，单类可上千行，折叠时丢的是大块内容。
2. **短有效上下文（小模型）**：标称 256K，有效召回远低于此。Chroma「Context Rot」实测 18 个前沿模型（含 Qwen3）无一例外随输入变长退化，200K 模型在 ~50K 就开始掉点（https://research.trychroma.com/context-rot ）。rev-agent 的 compactThreshold=160k **必然触发折叠**。
3. **折叠有损且不可自动恢复语义**：`compactHistory` 把旧 tool 结果 `output.value` 换成位置指针 stub，`reads[]` 只记「你读过 X 的 a–b 行」，**绝不提醒「你当时在那看到过一个 AES key」**。

成本量级：一次 re-derivation = 重 grep + 重 read（把千行大块重新 prefill）+ 长上下文里重推语义。在 input:output ≈ 100:1 的 agent 经济下（Manus 实测，https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus ），几乎所有算力花在 prefill，重读一个千行类几乎等于白烧一整轮 prefill，且重读进来的大块内容又加剧 context rot——「越查越差 + 越查越贵」的双输。

**但——（红队 §2 修正）这笔账两面都成立**：把发现「贴末尾注入」同样是在这条 100:1 的 prefill 账上持续烧钱，只是换了位置。见 §2 风险表与 §5.2。

### 2.3 关键结论：存在真实行业空白（但含义已被红队收窄）

跨 30+ 系统的一致判断：**几乎没有已发表/生产系统显式区分「当前目标 vs 顺路/off-goal 发现」并为后者设专门采集闸门 + 联想式回捞。** 最接近的是 Confucius、Claude Code Auto memory、Generative Agents。

**但红队 §3/§4 指出这个「空白」不一定是机会，可能恰恰是坑**：off-goal 内容按定义就是 context-rot 论文里的 distractor，主流系统「不专门为 off-goal 做常驻注入」很可能是刻意而非疏漏。用户想法是成熟 pattern 的合理增量组合，**不该神化其新颖性，也不该假设『没人做=蓝海』**。

## 3. 与 rev-agent 现有机制的精确重叠与真实缺口

已核对源码（`ledger.ts`、`note.ts`、`agent.ts`、`corpus.ts`）。

### 3.1 现有相关机制
- **Ledger 自动捕获 reads[]/greps[]**：零-LLM 记 `ReadEntry{path, ranges}`、`GrepEntry{pattern,path,hitCount}`。**`ReadEntry` 无任何语义槽——只有路径+行号。**
- **deriveEdges / promoteFromProse**：唯一从内容提炼的语义是**方法调用边** `Hop{from,to,evidence,corroborated}`，保守到极致。
- **compactHistory 折叠**：ctx≥160k 换位置指针 stub，丢的正是内容本身。
- **append_note**：唯一写盘、可承载任意 verbatim 语义（schema 例子正是「发现：sign 调到 native」），**已 appendFile 持久化**；但 `classify:()=>'ask'` 永远弹审批、正文 ≤2KB、纯散文、不去重、不可查询、不回注、完全靠模型自律。
- **corpus.ts 案卷模式**：已有出处分级 + 三角验证 + 反幻觉纪律（红队补，草稿漏）。

### 3.2 精确重叠（别重造）
1. **导航去重（子问题 A）已完全覆盖**：`dedupHit + hasRead/hasGrep`。用户想法里「避免重复读取」这一半是重述。
2. **调用链留存已覆盖**：deriveEdges + promoteFromProse → hops，带证据+交叉核验，收尾 `renderChainGraph` O(1) 复用。**唯一已被结构化缓存的语义类别。**
3. **可逆指针已覆盖**：折叠留 path+range+reread 指令，markEvicted 允许按需重读（Manus 可恢复压缩的本地版）。
4. **持久化 + 任意语义留存已部分覆盖（红队新增）**：`append_note` 已写盘、已能承载任意 verbatim 语义。它缺的**只有三点**：不自动、永远审批、不回注。**这直接改变了「最小修复」的形态（见 §4、§6）。**

### 3.3 真实缺口
1. **语义留存维度只有一种（调用边）**：硬编码 key/常量/URL、flag 条件返回、实现接口、数据流、「此处 native/混淆/加壳」这类**非调用边发现，现有结构一律看不到**。
2. **自动抓的结构不跨会话存活**：Ledger 纯进程内存，`fromJSON` 零调用、resume 不读 ledger，进程一退全蒸发。跨会话存活的只有 append_note 散文，而它靠自律。
3. **无可查询/去重的发现库**：note append-only 不可查不去重；ledger 结构化但短命且无「后续回查是否已发现过 X」接口。

### 3.4 与「上下文记忆系统 V2 设计」的关系（重要警示）
- 设计 §3.9（ledger snapshot 落盘 + resume 种子重建）**已被红队判为「镀金/降级、非实测痛点」并显式排除**。
- §8.3 因「实测 folded=0、body 从不膨胀」暂缓落盘。
- **含义**：用户想法「把 ledger 持久化」是在重提一个「设计已有据排除」的项。落地前必须先拿出**顺路发现确实丢失且有价值**的实测证据，否则触碰「防过度设计」红线。

## 4. 精炼后的设计（**主路径已按红队对调**）

设计目标：补 §3.3 缺口，**同时不破 SWA 稳定前缀、不加剧 context rot、不与 Ledger 造重复系统、不违反 corpus 反幻觉纪律**。

### 4.1 草稿原主张（已被否）与修正后主张

草稿原主张：**新建第五数组 `findings[]` + 零-LLM 正则抽取引擎 + offGoal 标记 + 有界注入**为主路径；改造 append_note 为「并行补充、非主路径」。

**修正后主张（采纳红队 §1）**：主路径与后备**对调**。

- **修正后的 MVP（阶段1）** = **复用已持久化的 `append_note`**：
  1. 把 `classify: () => 'ask'` 从常量放宽为「append 到既有 notes 文件时非 ask（仍写盘、可审计）」；
  2. 把 notes 文件尾部拼进**已经存在**的末尾 ephemeral 块（agent.ts:321 那条管道）；
  3. 细节靠 file:line 指针按需重读。
  - **零正则、零新数据结构、零 offGoal、复用持久层、复用回注管道、天然满足 SWA。**
- **正则自动抽取降为『待证的后备』，且必须改用 LLM 判语义（方案 B），不能用正则**（采纳红队 §5）。
- **第五数组 `findings[]` 在阶段1 不建。**

### 4.2 为什么正则自动抽取被否（采纳红队 §5，草稿此处过度乐观）

「高精度低召回正则」在 jadx 反编译产物上是幻想：
- 大 APK 里 `Cipher.getInstance`、硬编码字符串、`native` 修饰**遍地都是**：正则要么狂喷噪声（瞬间撑爆预算、塞垃圾），要么阈值收紧到**在最该起作用的混淆 APK 上什么都抓不到**（类名被改 `a/b/c`、字符串加密拆分，命中率趋零）。**恰好在最需要它的样本上失效。**
- 正则做不了语义判断：`Cipher.getInstance("AES")` 出现在缓存工具类 ≠「sign 的 key」，抓出来很可能是**假线索**。
- `offGoal`「kind 与 goal 关键词无交集」是粗暴关键词匹配，误标率高。

结论：**零-LLM 正则自动抽取整个砍掉。** 若阶段0 证明确有价值，捕获走 LLM（方案 B）+ 强制独立二次核验；正则最多做候选高亮，绝不直接落成「发现」。

### 4.3 为什么 offGoal 常驻注入被否（采纳红队 §3，草稿存在内在自相矛盾）

草稿引 Context Rot / Lost-in-the-Middle 论证「无关上下文拖垮当前任务」，却又提议把 `offGoal=true`（按定义与当前子目标无关）持续注入每一步——**offGoal 发现正是那些论文定义的 distractor。用「无关上下文有害」论证「常驻注入无关上下文」，方向反了。**

对小模型这几乎必然是**当前步定位精度的净损失换未来一次不确定的省读**（确定的每步税 vs 投机的、Confucius +1.4pp 级的未来收益）。

修正：**offGoal 发现默认不进注入块，只落盘 + 留 file:line 指针，需要时才召回**——这恰好退化成「写个 note + 按 file:line 重读」，即 §4.1 的 MVP。**offGoal 注入逻辑整个砍掉。** 只有 on-goal（与当前 goal 关键词有交集）的发现才允许进有界注入。

### 4.4 取回方案对比（结论不变，理由收紧）

| 取回方式 | 说明 | 适配？ |
|---|---|---|
| 全量注入 | 每步拼所有发现 | ❌ 加剧 rot、且撑爆 4000 字符预算 |
| 紧凑索引注入（**仅 on-goal**） | 只在既有台账块内加极少条，与 hops/reads **竞争同一 4000 字符预算**，优先级最低 | ⚠️ 有条件可用（见 §5.2） |
| 检索（embedding/BM25） | 按 query 取 top-k | ❌ 本地无嵌入服务、单并发、发现量级不值得建索引 |
| **按需重读指针** | 只存 file:line，模型想看自己重读 | ✅ **主取回方式**（指针可逆、零 rot、零税） |

## 6. 分阶段落地 + 消融实验设计（防过度设计）

### 阶段 0（前置，一票否决闸门）：证明痛点真实 **且** 小模型会用 note

写任何代码前，用现有题库跑 N 个真实逆向任务，插桩统计**两件事**（红队 §4/§7 把它从一件加到两件）：

- **痛点是否真存在**：多少次 read 内容含可识别语义发现？其中多少条在被折叠后又被重新 grep+read 发现一次（真 re-derivation）？烧了多少 token？
- **小模型是否会用留存通道**：在**不改任何代码**的前提下，给出/开放 `append_note`，观察小模型是否会主动写、是否会在后续读回。**若连既有 note 都不自律写/不读回，就没有任何证据支撑它会用一个更复杂的通道——直接不做。**

**阶段0 插桩自身的可信度必须先修（红队 §7）**：判定一次 re-derivation 需把新 grep/read 语义匹配到某条先前折叠发现，这套插桩极易高估/低估。**先在小样本上人工校准插桩，再信它给出的门槛数字。** 门槛：折叠后重新发现的频次/token 占比不可忽略（如 ≥某人工校准阈值）**且**小模型确实会用 note，两条同时满足才进阶段1。

### 阶段 1（MVP，最小可行增量）—— **修正后形态**

只做三件事，零正则、零新数据结构：

1. `append_note` 的 `classify` 从常量 `'ask'` 放宽为「append 到既有 notes 文件时非 ask（仍写盘、可审计）」。
2. 把 notes 文件尾部拼进**既有**末尾 ephemeral 块（agent.ts:321 管道），**在 4000 字符预算内、优先级最低**，措辞为「线索(未核验)」而非并入台账权威句。
3. 细节靠 file:line 指针按需重读。

**验收（离线可测部分）**：
- 单测：notes 尾部拼接不超预算、不挤掉 hops、不写回 this.messages、system 头逐字节不变（复用现有前缀不变单测思路）。
- **但注意（红队 §7）**：前缀不变单测只证「机制没坏」，**不证「有价值」**，绝不能当验收通过放行。

### 阶段 2（仅当阶段1 消融证明有用才做）
- 落盘 findings + resume 种子重建（即 §3.9，**需先推翻红队排除结论**）。
- 方案 B：folding 前一次性 **LLM**（非正则）抽取 + **独立二次核验**门槛。
- 结构化 `findings[]` 第五数组。

### 消融实验设计（红队 §7 已把目标从「证明有用」改为「证伪」）

在固定题库跑 A/B（lemonade 单并发，串行）：

| 开关 | 对照假设 | 判定标准（修正后：可判定的否定命题） |
|---|---|---|
| 全关 vs 全开 | 留存是否无害 | **主要看『证伪无害』**：若全开在 token/轮次/解决率任一项**显著变差**→砍。 |
| 只存不注入 vs 存+注入 | 隔离「存」与「用」 | 若注入无增益→**证伪『会被用』**→砍注入。 |
| on-goal 注入 vs 全部注入 | 验证 §4.3 | 已默认只注入 on-goal；此臂用于证伪「off-goal 注入有害」。 |

**关键诚实（红队 §7）**：
- Confucius 效应量 +1.4pp / −10% **已在噪声级**；lemonade 单并发串行、题库仅 ~30 题，**几乎拿不到统计显著**，读数只会被乐观解读。
- 判分铁律「模型引用了 finding 而没重 grep」是**不可观测的反事实**（一次「没发生的重读」无法归因到某条 finding），**这个直接价值指标实际测不了**，草稿原设计在此点上过于乐观。
- 因此接受**默认结论**：多半会因效应量太小/功率不足而**无法证明有用 → 按「不做」处理**。消融的作用是「证伪无害/证伪没人用」，不是「证明有用」。凡被证伪的开关一律删除。

## 9. 裁决

**当前形态（草稿的正则 findings 引擎）不该落地。** 只做阶段0 量化，且必须先修好它自身的插桩可信度。

理由：
1. **痛点真实**（§2：107-session 8% 冗余读、Confucius 量化、context rot、OfficeBench/LoCoBench 明确点名缺去重与增量追踪）。
2. **确有真缺口**（§3.3：现有 Ledger 只结构化留存调用边，非调用边语义发现无处安放；自动的不持久、持久的靠自律；无可查询发现库）。
3. **但草稿主路径押错了**：它建了最重的正则抽取引擎，而真正的最小修复是**复用既有已持久化的 `append_note`**（去掉 `classify:()=>'ask'` 常量审批 + 把 notes 尾部拼进已存在的末尾 ephemeral 块 + 按需重读），零正则、零新数据结构、天然满足 SWA。
4. **正则自动捕获与 offGoal 常驻注入必须砍掉**：正则在混淆产物上非噪即哑，且把未核验猜测以系统权威口吻注入直撞反幻觉红线，`corroborated` 过滤对 findings 恒真形同虚设；offGoal 常驻注入与 context rot 论据自相矛盾。除非日后用 **LLM 捕获 + 独立二次核验**重新证明，否则不碰。
5. **收益温和 + 检索悖论 + 功率不足**共同意味着：**多半无法证明有用，应按「默认不做」处理**。落地闸门在阶段0，而非工程热情。

**防过度设计的最小落地路径**：阶段0（痛点量化 + 小模型是否会用 note，先校准插桩）→ 双条件同时满足才进阶段1 →阶段1 只 un-gate append_note + 回注尾部（4000 字符预算内、优先级最低、措辞「线索(未核验)」）+ 指针重读，不建 findings[]、不落盘、不做 resume → 消融以「证伪无害/证伪没人用」为目标，被证伪的开关一律删除。
